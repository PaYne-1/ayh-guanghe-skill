# 产品视频技能启动沟通清单设计

## 目标

`product-video-pipeline` 每次开始新任务时，必须先向用户展示完整的启动沟通清单。清单一次说明用户需要提供的内容、当前计划采用的配置，以及本轮需要用户回复的项目。未获得明确回复前，不扫描产品素材、不初始化批次、不生成图片，也不调用付费接口。

## 交互结构

首次回复固定包含三个连续区块：

1. `你需要提供的内容`：产品文件夹、产品名称、卖点、视频数量、封面参考文件夹，以及任务所需的 API 或渠道接入状态。每项必须标记为 `已提供`、`待确认` 或 `需要提供`。
2. `本次配置明细`：运行模式、文本能力、生图路由、分镜尺寸、视频模型、工作流、时长、画幅、分辨率、水印、声音、并发、图片尝试次数、视频重跑次数、价格、预算、输出位置和规则库。未知项必须显示为 `待查询` 或 `待确认`，不得省略。
3. `请你回复`：只列出仍需用户决定或提供的项目，并给出可复制填写的回复模板。若所有内容都已有值，也必须让用户回复明确确认。

每次任务都展示完整清单，不能因为 API 已配置、使用同一产品或之前做过类似任务而跳过。后续只允许针对用户回复后仍缺失或互相冲突的项目进行一次汇总补问，不得边执行边零散追问。

## 安全与执行边界

- API Key 只询问“是否已通过安全环境变量接入”，不要求用户在聊天中粘贴密钥。
- 首次沟通清单本身不读取密钥、不扫描产品文件夹、不创建批次、不联网查询价格。
- 用户回复并允许检查后，才验证配置、扫描第一层素材、查询实时价格并生成最终启动确认单。
- dry-run 不联网、不扣费，必须明确说明；dry-run 通过不代表付费授权。
- 正式提交前仍需展示实时价格、单条费用、含一次重跑的最高费用和预算，并取得明确付费确认。

## 验收标准

1. 新鲜上下文只要触发技能，首轮就显示三个固定区块。
2. 即使 API 和产品路径已知，也仍展示全部配置，并要求明确回复确认。
3. 用户未回复前，不执行素材扫描、批次初始化、生图或付费提交。
4. 缺失项集中在 `请你回复` 中，用户可以复制模板一次填写。
5. 自测和项目测试通过，发布包与安装副本内容一致。

## 非目标

- 不改变 11 节点生产流程、模型工作流、首尾帧规则或人工验收规则。
- 不把首次沟通确认视为付费授权。
- 不自动填充用户没有明确提供、且会改变成本或成片方向的选择。
