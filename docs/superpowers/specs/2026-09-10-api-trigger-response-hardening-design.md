# API 配置触发与首轮回复修复设计

## 背景

实际宿主在收到 `配置API` 后虽然加载了 `product-video-pipeline`，但没有执行配置状态脚本，而是自行生成了错误选项：把 ChatGPT 网页端生图称为 `GPT Image API`、把 MiniMax 单独列为 API，并为首项添加 `Recommended`。这与技能已有的永久配置合同不一致。

## 目标行为

`配置api` 中拉丁字母按不区分大小写匹配，因此 `配置api`、`配置API`、`配置Api` 和 `配置aPi` 都进入同一 API 配置路由。该路由优先于产品视频启动路由。

触发后的第一个用户可见回复必须基于 `python scripts/api_config.py status` 的实际输出，并按以下顺序展示三个配置类别：

1. AutoDL.Art 视频 API
2. 第三方生图 API
3. 第三方文本生成 API

三项都是配置类别，不是生图渠道选择。回复不得添加默认项、推荐项或预选项，也不得出现“GPT Image API（ChatGPT 网页端生图）”或“配置 MiniMax API”。本机 Codex 和 ChatGPT 网页端依靠登录会话，不需要 API Key；MiniMax-H3 视频由 AutoDL.Art 视频 API 承载，不单独配置。

状态命令成功时，显示每类的“已配置/未配置”、非敏感字段和密钥末四位。状态命令不可执行或失败时，回复“无法读取当前配置状态”以及安全错误摘要，不得把任何类别猜成“未配置”，随后停止在配置路由中等待环境修复。

## 固定首轮回复结构

```text
当前 API 配置状态：

1. AutoDL.Art 视频 API（必需）：<真实状态>
2. 第三方生图 API（可选）：<真实状态>
3. 第三方文本生成 API（可选）：<真实状态>

本机 Codex 和 ChatGPT 网页端使用登录状态，不需要配置 API；MiniMax-H3 视频统一通过 AutoDL.Art。

请选择本次需要配置或更换的一项：
AutoDL.Art 视频 API / 第三方生图 API / 第三方文本生成 API
```

密钥只显示遮罩结果。选择类别后，才在本机交互式终端运行相应的 `configure --category` 命令并通过隐藏输入接收完整密钥。

## 实现范围

- 更新技能描述和 API 路由规则，明确大小写不敏感匹配与固定首轮回复结构。
- 更新 `references/api-configuration.md`，把状态命令设为首轮回复的强制数据源，并定义失败处理。
- 在 `api_config.py` 增加只读 `prompt` 命令，直接输出固定首轮回复，减少宿主自由改写空间。
- `prompt` 命令只读，不扫描产品目录、不创建批次、不联网、不 dry-run、不执行生成或付费操作。
- 同步更新仓库技能、发布包和已安装技能。

## 验证

- 离线测试四种大小写触发文本都能在技能说明中明确匹配。
- `api_config.py prompt` 的输出只包含三个正确类别，不含 `Recommended`、`GPT Image API` 或独立 MiniMax API。
- 使用内存配置存储验证已配置、未配置与遮罩状态。
- 模拟状态读取失败，验证不会输出推测状态或密钥。
- 运行技能自检、仓库完整测试、Python 语法检查和技能结构校验。

## 安全边界

本次修复不验证真实 API、不发起联网请求、不产生费用。永久配置与付费授权继续分离；用户后续更换 API 时重新触发配置路由。
