# 11 节点执行流程

## 1. 产品素材

- 用户给出任意产品文件夹路径；产品名默认取最后一级目录名，可覆盖。
- 只读取第一层 PNG/JPG/JPEG/WEBP，不递归，不修改原图。
- 用户提供卖点后直接使用，不二次确认。每个产品单独维护卖点库，不保存脚本分镜库。

## 2. 内容策划

一个卖点对应一条独立视频。分析适用人群、使用场景、核心痛点、切入角度和选题方向，不判断疾病或伤情。输出内容契约规定的完整 JSON。

标题和正文先分别保存为 `_工作文件/生成过程/标题.txt` 与 `_工作文件/生成过程/发布正文.md` 候选。用户对具体候选明确通过后，使用 `review-output` 按 SHA-256 晋升一级固定产出；不得直接写一级文件。

默认每个卖点一套。用户指定总数量时平均分配，余数从第一个卖点开始分配。例如 5 个卖点生成 23 条：5、5、5、4、4。

## 3. 分镜图和封面图

- 当前 Agent 有原生生图能力时默认使用；没有时使用启动确认单中的生图 API。
- 自动从产品图选择 1 张主参考和最多 2 张辅助参考。
- 每条生成 1 张竖屏 4K 分镜候选到 `_工作文件/生成过程`，固定为 `2160×3840`、`9:16`。生成后必须核验实际像素尺寸；不足 4K 不得进入后续节点。外形相似度目标不低于 90%，无大面积变形，Logo 不改变，人物清单一致。用户明确通过并记录候选 SHA-256 后才晋升为一级 `分镜图.png`。
- 最多生成 3 次；第三次仍失败只标记该视频需要人工处理，批次其他项目继续。
- 从用户确认的封面参考文件夹第一层选风格图，以合格分镜为底图生成相近的电商封面视觉包装；不得只做普通矩形底框叠字，也不得重画或改变产品结构、人物和构图主体。
- 参考风格由 Agent 根据画面内容、背景色和卖点自动选择，并在同一批次及相邻批次中轮换；不得每次固定套用同一张参考图或同一种版式。可在黄色撕纸、蓝色撕纸、橙色气泡、撞色拼贴等参考方向间选择。
- 封面标题必须与 `_工作文件/生成过程/封面标题.txt` 完全一致。生图文字不准确时，用 `render_cover.py --title-file _工作文件/生成过程/封面标题.txt` 确定性修正中文；Windows 不直接通过命令行参数传中文标题。
- 封面先输出到 `_工作文件/生成过程` 作为候选，用户明确通过并绑定 SHA-256 后才晋升为一级 `封面图.png`。

## 4. 发布正文

根据最终脚本和合格分镜生成 80–150 个汉字，标签不计入字数。人物、性别、场景、卖点与脚本一致。爱优护配置追加固定四个标签。

正文候选保存在 `_工作文件/生成过程/发布正文.md`；只有用户对该文件明确通过后，才晋升为一级 `发布正文.md`。

## 5. 视频参数

MiniMax-H3、15 秒、9:16、默认 768P；2K 只能在启动确认时选择。参考图使用合格分镜和原始产品图，关闭 AIGC 画面水印。新视频在付费视频提交前先生成独立口播音轨：按人物清单匹配身份、性别和年龄感，完整播放时长必须在14秒内，结尾至少预留约1秒自然停顿。必须先核对台词、说话顺序、无漏词、无改词、无截断，并保存 `_工作文件/生成过程/口播音轨.wav` 与 `_工作文件/验收记录/口播音轨验收.md`；不合格时先修改或重生成音轨，不得进入视频付费提交。

对话式脚本以 `script_segments[].speaker_id` 为唯一说话人分配依据。脚本中出现两个或以上不同说话人时，每个不同 `speaker_id` 必须使用可区分的独立人物音色，并与 `people` 中对应人物的身份、性别和年龄感一致。先分别生成每个角色的台词片段，再按照脚本时间段合成为一条最终音轨；不得整条使用同一音色，不得让同一个人物包办其他人物台词。音轨生成后由系统逐段核验时间段、`speaker_id`、台词、音色身份和说话顺序，系统自动验收，不设置用户试听确认节点。任何缺少说话人、音色不可区分、说话顺序颠倒或自问自答都自动判为不合格，不得进入付费视频提交。

独立音轨通过后，默认使用 `minimax_h3_image_audio_to_video_v2_15s`，以合格分镜、原始产品图和已验收音轨生成视频。视频阶段只负责行驶画面、自然动作、口型同步和轻微环境声，不重新创作台词，不加 BGM。新视频没有历史音轨时必须执行上述音轨前置步骤；只有失败恢复任务可以在人工确认后复用上一版已经验收完整的音轨。

行驶双人对话场景优先使用合理尾帧首尾帧模式：以已通过的竖屏 4K 分镜图作为 `2160×3840` 首帧，另行生成同尺寸尾帧，尾帧不得复用首帧。尾帧以分镜为主要视觉基准、产品原图只用于校正结构，模拟主体继续向前约 1–1.5 米后的合理状态：背景透视后移、车轮产生合理转动、陪护者进入下一步步态。首尾保持相近的主体屏幕位置、人物比例、中远景尺度、安全边距、曝光、白平衡和整体亮度；老人、陪护者和整车完整可见，两人对话时自然看向对方。尾帧必须先通过像素尺寸、主体完整度、产品结构和首尾视觉一致性检查，才可进入付费确认。

已通过分镜是视频画面的视觉基准。视频必须保持分镜中的人物完整度、产品角度、构图、亮度、曝光、白平衡和色温，只允许在该画面上增加已策划的轻微动作与对白。人物被裁切、产品朝向改变、镜头重新取景或画面明暗与色调明显漂移时，自动判为视频不合格；不得用技术指标通过替代视觉一致性验收。

合理尾帧模式允许真实直线行驶产生连续、自然的视角演进和轻微亮度波动，这些变化记录时间点进入复核，不单独自动判为硬失败；切镜、突然切近景、人物持续裁切、产品结构变形、轮椅未真实行驶或首尾脱离已通过分镜仍是不合格。

视频全程必须一镜到底，禁止切镜、跳切、转场、突然推近、突然拉远和景别突变。允许摄影机缓慢、连续、平稳运镜，但运镜过程中人物完整度、轮椅角度、主体构图、曝光、白平衡、亮度和色温仍须保持已通过分镜的视觉基准；人物中途出框、产品主体被裁切或产品展示角度明显改变时，自动判为视频不合格。

付费提交前必须确认全部口播能在 15 秒内按自然聊天语速完整说完并留出结尾停顿。超限时先自动精简台词，保留本条唯一卖点、使用改善和结尾了解引导，重新检查通过后才可提交。禁止用加速抢读、漏词、改词或截断尾句来迁就时长。

以上“一镜到底、连续平稳运镜、完整口播”三项硬规则必须覆盖整个0–15秒，包括首帧、全部中间过程和尾帧；不得只在开头或结尾满足。使用首尾帧工作流时，已通过分镜首帧和独立生成的合理行驶尾帧只加强端点约束，视频提示词仍必须逐项声明三项规则全程有效。

## 6. 提交 AutoDL.Art

先内容、图片、预算和请求哈希检查，再 dry-run。学习模式在策划和图片确认后自动提交；自动模式在规则检查通过后提交。正式提交必须在已确认预算内。

## 7. 保存 task_id

成功响应后立即写入本条 `_工作文件/任务状态/任务信息.json` 和批次 `批次任务表.json`。已有 task_id 或相同请求哈希不得重复提交；超时且不确定是否提交成功时标记 `SUBMIT_UNKNOWN`。

## 8. 查询状态

默认每 20 秒查询，网络错误最多连续重试 5 次，连续等待 60 分钟后标记查询超时但保留 task_id。批量结束统一汇报，不逐条打扰用户。

## 9. 下载 MP4

成功后立即下载为 `_工作文件/生成过程/视频候选.mp4.part`，完成并校验后原子改名为 `_工作文件/生成过程/视频候选.mp4`。下载最多 4 次。检查非空、容器、约 15 秒、9:16、目标分辨率、有效非静音音轨和可解码画面。候选不得直接命名为一级 `视频.mp4`。

## 10. 批量人工验收

生成一个 `批次验收报告.html`，每条一张卡片。报告可预览 `_工作文件/生成过程` 中的待验收视频候选，并显示候选相对路径和 SHA-256，但不得把候选当成一级正式产出。用户必须为每条选择通过或不通过；不通过必须写原因。最终视频永远由用户验收，自动报告不能替代。

旧格式批次结果没有候选路径和 SHA-256 时只保存反馈，不能自动晋升。视频必须通过 `review-output` 绑定本次候选哈希和用户明确通过反馈后，才晋升为一级 `视频.mp4`。

## 11. 复盘与一次重跑

失败原因分流到内容、分镜、封面、音频、视频、API、轮询、下载或模型能力边界。学习模式中用户提出的任务相关问题必须立即调用 `record-issue` 形成结构化候选经验。V01 不通过后只允许 V02 重跑一次；对应检查通过且用户明确通过 V02 后调用 `validate-learning --result passed`，自动升级正式规则，不再单独询问是否升级。V02 仍失败或无法判断是否解决时分别记录 `failed` 或 `inconclusive`，不得进入正式规则。新批次和每个节点开始前必须调用 `prepare-node-rules` 并实际应用命中动作。

## 文件结构

```text
产品文件夹/生成视频/YYYYMMDD_批次NNN/
├─ V001_卖点_封面标题/
│  ├─ 标题.txt
│  ├─ 分镜图.png
│  ├─ 封面图.png
│  ├─ 发布正文.md
│  ├─ 视频.mp4
│  └─ _工作文件/
│     ├─ 任务状态/任务信息.json、查询结果、提交请求与 AutoDL 响应
│     ├─ 生成过程/标题.txt、发布正文.md、分镜候选、封面候选、视频候选、提示词、音轨与转写
│     ├─ 验收记录/产出验收记录.json、口播音轨验收.md、自动验收报告.md、人工验收结果.md
│     └─ 历史版本/验收候选、候选版本、未通过或待验收、已撤换产出、视频版本及失败版本
├─ 批次任务表.json
├─ 批次汇总.md
├─ 批次验收报告.html
├─ 批次验收结果.json
└─ 批次验收结果.md
```

单条任务第一级只允许五项经过明确通过的最终产出和 `_工作文件`。每个一级文件必须能在 `产出验收记录.json` 中找到同一产出名、同一 SHA-256 且最新决定为 `passed` 的事件。没有明确通过则一级目录不保留对应文件；失败、撤销、无记录、记录损坏或哈希不一致的文件由 `audit-outputs` 移入 `历史版本/未通过或待验收`。过程文件必须分别写入 `_工作文件/任务状态`、`_工作文件/生成过程`、`_工作文件/验收记录`、`_工作文件/历史版本`。

验收事件按追加顺序判定最新决定，不依赖系统时间排序；写入时使用跨进程锁。`review-output` 将被验收字节复制为 `_工作文件/历史版本/验收候选` 下的不可变快照，事件绑定该快照。重复生成同名候选前，旧候选移入 `历史版本/候选版本`。晋升采用同盘临时文件、哈希校验和失败回滚，不能因复制失败丢失原一级产出。

```powershell
python scripts/workflow_cli.py review-output --item-dir "单条任务目录" --artifact "分镜图.png" --source "_工作文件/生成过程/分镜候选.png" --decision passed --confirmed-by "用户" --feedback "明确通过"
python scripts/workflow_cli.py audit-outputs --item-dir "单条任务目录"
```

后续节点读取一级产出前必须再次校验验收事件和哈希，不能只判断文件是否存在。旧 Markdown 或旧批次 JSON 只供查阅，不得推断或补造 `passed` 事件。
