# 交互与最终交付契约

## 自动 V01 交付

自动模式从首次回复的授权开始，连续执行内容、已锁定生图渠道的三张原生 图片和 V01；本批次最高总预算只统计视频费用，图片和文本不计入且可能另行收费。图片不设置人工审核节点，也不进行模型视觉审核；V01 也不设置自动语义审核。技术检查通过即返回 `V01_DELIVERED`，状态 `WAITING_USER_FEEDBACK`。

每个交付行必须包含：

```json
{
  "video_id": "V001",
  "video_path": "真实存在的绝对路径",
  "item_dir": "真实存在的绝对路径",
  "sha256": "候选和交付文件一致的 SHA-256",
  "technical": {"ok": true, "full_decode": true},
  "video_cost_yuan": "V01 成本",
  "image_cost_yuan": "图片成本",
  "status": "V01 已下载，等待用户反馈"
}
```

运行器必须重新解析、验证文件存在且为绝对路径，验证其不在临时目录、位于对应项目一级目录，并把相同数据写入 `批次V01交付.json`。Windows 路径以正斜杠展示，含空格时使用尖括号。没有通过这些检查不得交付。

## 音频试听（技术通过不等于口播通过）

自动V01交付增加audio_review，默认pending_listening。运行器在_工作文件/验收记录/音频试听.json保存视频SHA256、原台词和交接停顿时间表。必须完整试听全片，重点听每次交接及开头/结尾，核对台词、说话人、重叠和额外伪语音。转写仅辅助，听不懂的伪语音可能漏识别；没有可用听辨能力时直接请求用户试听，不得声称听过或自动判通过。

收到真实试听结论后，可执行：python scripts/audio_review.py --video "实际视频路径" --report "对应音频试听.json" --verdict passed或failed --reviewer "实际试听人" --notes "结论及异常秒数" --listened-full。脚本核对视频哈希；替换视频或台词计划后旧结论失效。不得伪造试听人或根据解码/转写结果填写passed。failed必须明确告知用户，不能推荐为口播合格成片；保留原文件，不自动静音或重生成。pending_listening只表示已下载待试听，不是质量通过。本工具不提供自动ASR或伪语音识别。

## 用户反馈和 V02

V01 的语义缺陷不由系统自动判断。只有用户在 `WAITING_USER_FEEDBACK` 提出反馈后才使用 `request-rerun` 记录问题；该命令不付费、不归档 V01、不增加重跑次数。之后必须显式批准该视频的 V02 费用；V02 完成后进入人工验收，禁止自动 V03。

## 图片和产品参考

分镜、尾帧、封面均为**渠道支持的原生分辨率**；禁止本地放大、裁切、拉伸、补画和重绘。所有生成上下文都声明**产品参考图是唯一产品依据**，禁止用文字重新描述产品外观。图片技术通过后自动晋升，仍保留 SHA-256 与候选路径。

## 七项最终产出

一级目录只保留 `标题.txt`、`发布正文.txt`、`话题标签.txt`、`分镜图.png`、`尾帧图.png`、`封面图.png`、按发布标题清洗命名的 MP4 和 `_工作文件`。每个一级产出都必须有匹配的 SHA-256 和通过事件。自动 V01 交付仅表示等待反馈；学习模式或 V02 的最终完成仍需七项最终产出全部有效。

## 人工反馈定位知识（不得注入生成提示词）

交付问题可使用路径、哈希、时间点和参考图定位；不得把任何产品组件或外观事实回填至分镜、尾帧、封面或视频提示词。
