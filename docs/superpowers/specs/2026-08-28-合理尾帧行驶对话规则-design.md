# 合理尾帧行驶对话规则设计

## 背景

本次已验收的视频采用 MiniMax H3 首尾帧工作流：以通过验收的 4K 分镜图作为首帧，另行生成体现真实前进行驶状态的合理 4K 尾帧，再由模型在两帧之间生成连续行驶画面。该结果得到用户明确通过，现将其沉淀为“行驶对话场景”的优先规则，而不是所有视频的统一默认工作流。

## 适用范围

当脚本同时满足以下条件时，优先采用合理尾帧首尾帧方案：

- 核心画面是轮椅真实向前行驶；
- 画面包含老人和一名陪护者或家属；
- 脚本需要由两名角色完成对话；
- 需要尽量保持视频与已通过分镜的构图、人物完整度和产品结构一致。

陪护者身份不得固定为女儿，可以按脚本设定为儿子、女儿、孙子、孙女、配偶、护理人员或其他合理角色。规则使用“提问者/陪护者”和“老人/乘坐者”作为抽象角色。

无行驶、单人口播、纯产品展示或其他不适合首尾帧插值的场景，继续按现有工作流路由，不强制套用本方案。

## 分镜与合理尾帧

- 首帧必须使用已通过验收的竖版 4K 分镜图，默认尺寸为 2160×3840。
- 尾帧不得简单复用首帧，也不得从无关图片生成；必须以已通过分镜为主要视觉基准，以产品原图仅校正轮椅结构。
- 尾帧模拟首帧之后约 1–1.5 米的自然前进行驶状态：背景透视后移、车轮有合理转动、陪护者步态向前推进。
- 首尾帧保持相近的主体屏幕位置、人物比例、中远景尺度、安全边距、曝光、白平衡和整体亮度。
- 老人、陪护者及整车必须完整可见；四轮、连续式脚踏板、靠背、扶手、控制器和车架关系不得改变、分离或畸变。
- 对话期间两名角色应自然看向对方，不允许两人长期各看各处或只有身体侧边入镜。
- 尾帧生成后先完成尺寸、主体完整度、产品结构和首尾亮度一致性检查，再允许提交付费视频任务。

## 脚本规则

行驶对话场景必须使用真正的双角色对话，不能由老人自问自答，也不能把所有台词写成单人口播。

标准结构为：

1. 提问者/陪护者提出与本次卖点相关的简短问题；
2. 老人/乘坐者用自然口语回答，并明确表达实际乘坐感受和本次产品卖点；
3. 结尾由老人或已在脚本中明确指定的角色说出下单类行动指令。

下单类行动指令必须明确包含购买意图，例如“可以直接下单购买”“需要的话现在就能下单”“点击下方立即选购”。仅说“了解一下”“看看吧”“挺不错”不算有效行动指令。

生成前必须固化角色与台词映射，并在提示词中逐句标注说话人。角色身份可变，但同一条视频内的说话顺序和台词归属不得漂移。

## 视频生成规则

- 使用 `minimax_h3_lightx2v`（MiniMax H3 首尾帧生视频）并同时传入合格首帧和合理尾帧。
- 视频表现为一镜到底、连续平稳跟拍、轮椅真实向前行驶；禁止主动切近景、切镜头或突然改变构图。
- 提示词必须全程约束人物完整、产品完整、两人自然对视、连续行驶和完整说完所有台词。
- 该工作流没有独立参考音频输入时，允许使用模型原生对话音轨，但生成后必须执行台词和角色核验。
- 未经用户确认，不得因一次失败自动发起新的付费任务。

## 验收与反馈学习

硬性不合格项包括：

- 明显切镜头或突然切近景；
- 陪护者或老人被持续裁切、脸部长期不可辨认；
- 轮椅、四轮、脚踏板、控制器或车架结构变形、分离；
- 轮椅没有真实行驶；
- 角色自问自答、台词串角色、关键台词缺失或语音不可理解；
- 结尾没有有效的下单类行动指令。

连续行驶导致的自然视角变化、轻微亮度波动或模型插值过渡，不在本模式下单独自动判为硬失败；应记录时间点作为复核证据。只要画面连续、主体与产品完整、无结构变形且首尾视觉仍与分镜一致，可交由用户最终判断。

用户明确说“视频通过”或认可结果时，以用户验收结论为最终状态；自动检查结果保留为证据，不覆盖用户的明确结论。

## 测试要求

规则更新应至少覆盖以下行为测试：

- 行驶双人对话场景优先路由到合理尾帧首尾帧工作流；
- 规则不把陪护者固定成女儿，允许多种合理人物关系；
- 首尾帧均为竖版 4K，且尾帧必须是独立生成的合理行驶状态；
- 双角色脚本包含提问、回答和下单类结尾指令；
- 自问自答、缺失 CTA、人物裁切及产品结构错误均被定义为不合格；
- 自然视角和轻微亮度变化只进入复核，不在该模式下单独自动硬失败；
- 用户明确验收通过可以覆盖自动报告的最终状态，但不删除检测证据。
