# 七项一级正式产出设计

## 目标

把单条视频项目的一级正式产出从五项调整为七项：发布正文与话题标签拆分为两个文件，独立合理尾帧以 `尾帧图.png` 作为第二张正式分镜进入一级目录。

## 一级目录契约

单条项目第一级只允许以下七项正式产出和 `_工作文件`：

```text
标题.txt
发布正文.txt
话题标签.txt
分镜图.png
尾帧图.png
封面图.png
视频.mp4
_工作文件/
```

七项文件必须分别获得用户对当前候选的明确“通过”，并由 `review-output` 绑定候选路径和 SHA-256，才允许晋升到一级目录。自动检查、技术检查、文件存在或等待验收不能代替用户明确通过。

## 正文与标签

- `_工作文件/生成过程/发布正文.txt` 只保存正文内容和结尾换行，不再附加话题标签。
- `_工作文件/生成过程/话题标签.txt` 单独保存内容契约中的全部标签，按单行空格分隔并以换行结尾。
- `发布正文.txt` 与 `话题标签.txt` 分别验收、分别记录哈希、分别晋升。
- 修改正文不得自动改变已通过的话题标签；修改标签也不得自动撤销已通过正文。新候选覆盖前仍按现有候选归档规则保存旧版本。

## 两张正式分镜

- 已通过的 `2160×3840` 正式首帧候选晋升为一级 `分镜图.png`，作为 `first_frame`。
- 依据首帧独立生成的同尺寸合理尾帧候选保存为 `_工作文件/生成过程/尾帧候选.png`。
- 尾帧先通过尺寸、主体完整度、产品结构和首尾一致性检查，再由用户明确回复“通过”；通过后晋升为一级 `尾帧图.png`，作为 `last_frame`。
- `尾帧图.png` 不得复用 `分镜图.png` 的字节，两个文件必须分别记录 SHA-256。
- 视频 dry-run 和付费提交前必须同时验证一级 `分镜图.png` 与一级 `尾帧图.png` 均具有有效的最新 `passed` 事件和匹配哈希。

## 工作文件归档

- 当前待审候选保存在 `_工作文件/生成过程`。
- 验收事件、候选路径和 SHA-256 保存在 `_工作文件/验收记录`。
- 被替换、未通过、撤销、无有效证据或哈希不一致的文件进入 `_工作文件/历史版本` 对应分类。
- 状态、提示词、请求、响应和自动检查证据继续按现有分类保存，不进入一级目录。

## 代码与文档范围

- `workflow_cli.py`：把固定产出集合扩展为七项，拆分正文与标签落盘，允许并审计 `尾帧图.png` 和 `话题标签.txt`。
- `SKILL.md`、`workflow.md`、`content-contract.md`、`image-generation-routing.md`、`review-learning.md`、`startup-checklist.md`：统一七项目录、两张分镜和分别验收规则。
- `self_test.py` 与仓库测试：覆盖七项一级白名单、正文不含标签、标签独立文件、尾帧独立验收和旧五项表述消失。
- 版本提升到 `1.6.0`，同步本机安装副本并生成 `release/product-video-pipeline-v1.6.0.zip`。

## 兼容与失败处理

- 不自动改写历史批次。历史五项目录和旧版正文仅作为原始历史证据保留；新候选按七项规则执行。
- `audit-outputs` 对当前规则下缺少有效通过证据的一级文件执行现有撤下逻辑，不伪造通过事件。
- 尾帧结构检查不通过或用户未通过时，`尾帧图.png` 不进入一级目录，视频不得提交。
- 单项失败不扩大为整个批次失败；其他项目继续。

## 验收标准

1. 新内容包保存后，正文候选不包含任一固定标签，标签候选与 `hashtags` 数组内容一致。
2. 七个一级文件均能独立执行 `review-output`，未通过文件不会留在一级目录。
3. `尾帧图.png` 与 `分镜图.png` 均有独立通过事件和不同 SHA-256。
4. 所有文档不再声明“五项正式产出”或“尾帧不进入一级目录”。
5. 完整测试、技能自检、官方校验、安装副本哈希和发布 ZIP 解压自检全部通过。
