# GitHub 技能设计

## 目标

在当前仓库新增一个名为 `github` 的项目内 Codex 技能，使后续涉及 Git、GitHub API、提交和推送的任务优先使用已安装的 GitHub CLI 与系统凭据存储完成认证。

## 文件结构

```text
skills/
└── github/
    └── SKILL.md
```

技能保持单文件、自包含，不增加脚本、令牌文件或重复的 GitHub CLI 文档。

## 触发范围

技能描述覆盖以下意图：

- 使用 `gh api`、Pull Request、Issue、Release 或仓库元数据；
- Git 提交、拉取或推送需要 GitHub 认证；
- 排查 `gh auth`、HTTPS 凭据助手或远程仓库访问问题；
- 用户明确要求提交并推送当前工作。

普通的本地文件编辑不会触发该技能。

## 工作流

1. 确认当前目录属于 Git 仓库，并检查工作树、当前分支及远程地址。
2. 运行 `gh auth status` 验证登录；认证缺失时引导交互式登录，不把令牌写入命令、技能或仓库。
3. GitHub API 操作使用 `gh api`，Git 远程操作使用 Git；HTTPS 认证复用 `gh auth setup-git` 配置的凭据助手。
4. 提交前明确本次文件范围，只暂存与请求相关的路径，保留用户已有修改和未跟踪文件。
5. 运行与变更风险相称的验证，复核暂存差异后创建提交。
6. 默认推送当前分支到已有 upstream；没有 upstream 时使用 `git push -u origin <branch>`。
7. 推送后用本地分支与 upstream 状态或远程引用验证结果。

## 安全边界

- 永不在 `SKILL.md`、脚本、Git 配置、提交消息或工具输出中保存、回显个人访问令牌。
- 不使用 `git add .`、`git add -A` 等宽范围暂存方式处理脏工作树。
- 不执行强制推送、历史改写、分支删除、仓库创建或权限变更，除非用户明确授权。
- 认证失败、远程冲突、受保护分支或目标不明确时停止，并报告可验证的原因。
- 不因“提交并推送”而擅自包含无关文件。

## 错误处理

- `gh` 未安装：报告缺失并使用官方安装方式；安装完成后重新验证版本。
- 未登录或令牌失效：使用 `gh auth login` 重新认证；不请求用户在聊天中粘贴令牌。
- 远程不是 GitHub：继续使用普通 Git 工作流，但不假设 `gh api` 可管理该远程。
- push 被拒绝：读取拒绝原因；需要整合远程变更或改变历史时先征得用户同意。
- 工作树包含无关变更：按显式路径暂存，并在提交前检查 `git diff --cached`。

## 验证标准

- 技能目录和 YAML frontmatter 符合 Codex 技能格式。
- 描述能够准确触发 GitHub API、Git 提交和 push 场景。
- 测试场景证明技能会保护令牌、隔离无关变更、拒绝未经授权的强推，并验证推送结果。
- 最终提交只包含本设计文档和 `skills/github/SKILL.md`；仓库原有未跟踪文件保持未暂存。
