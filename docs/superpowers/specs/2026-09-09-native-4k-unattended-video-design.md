# 原生 4K 产品一致性与无人值守视频设计

日期：2026-09-09

## 目标

优化产品视频流水线的图片与 MiniMax-H3 视频提示词，降低产品结构变化、频繁切镜、人物腿脚残缺、口播重复和额外异常人声。自动模式在用户首次提供任务资料及总预算后，无人值守完成 V01 的策划、生图、提交、轮询、下载和文件整理，并返回真实存在的最终文件绝对路径。

本次只修改源码规则、提示词契约、状态机和离线测试。版本升级与完整技能发布包继续暂缓。

## 模式边界

- 本设计的无人值守规则只适用于 `auto` 模式。
- `learning` 模式继续保留现有分步确认能力。
- 自动模式不进行图片内容审核或视频语义审核，也不使用模型二次判断产品、人物、镜头和口播质量。
- 本地确定性技术检查继续保留，包括文件存在、媒体可解码、尺寸、时长、音轨、路径和 SHA-256 绑定。

## 一次启动输入与授权

自动模式第一次只向用户展示一份输入清单，收集：

- 产品文件夹路径；
- 产品名称和卖点；
- 视频数量；
- 生图渠道：`GPT 网页端` 或 `第三方 API`；
- 视频分辨率；
- 本批次最高总预算；
- 选择第三方 API 时所需的非敏感接口配置和单张价格。

用户回复这份清单即同时表示：

1. 本批次配置确认；
2. V01 一次性付费授权；
3. 内容、图片、封面、视频提交、轮询、下载和整理的连续执行授权。

自动模式不得再要求第二次“确认执行”，也不得在策划、分镜、尾帧、封面或 V01 下载后插入人工确认节点。只有预算不足、必要配置缺失、付费提交状态不明或其他无法安全恢复的硬阻断才暂停并报告。

## 单一总预算

用户只填写 `本批次最高总预算`，不分别填写视频预算和图片预算。系统内部仍保留独立费用账本：

- 第三方图片 API 费用账本；
- AutoDL V01 视频费用账本。

预计总费用为第三方 API 预计生图费用与全部 AutoDL V01 费用之和。选择 GPT 网页端时，图片 API 费用按零处理，不改变用户可能已有的网页订阅成本说明。

系统查询或读取单价后，先为全部 V01 视频预留预计费用；只有剩余总预算可以供第三方图片 API 调用及允许的图片重试使用。这样不能因图片调用先耗尽预算而导致已计划的 V01 无法提交。

- 预计总费用不超过总预算时直接进入自动执行，不再次询问。
- 预计总费用超过总预算时，不产生任何新的付费动作，并报告需要减少数量、调整渠道或提高总预算。
- 同一动作的恢复、轮询和重复回执不得重复计费。
- V02 不属于首次总预算授权范围。

## 产品参考图唯一依据

分镜图、合理尾帧、完整封面和视频提示词必须使用同一条产品一致性规则：

> 上传的产品参考图是唯一产品依据。直接使用参考图中的产品，保持结构、部件、比例、连接关系和相对位置完全不变。禁止重新设计、补画、删减、替换或推测任何产品部件。

提示词不得自行描述产品颜色、踏板形状、车架结构、轮胎样式、控制器外形或其他具体外观。产品型号规则可以用于本地一致性知识和人工反馈定位，但不得把外观描述重新注入生成提示词，避免文字描述覆盖参考图并诱导模型重画产品。

提示词必须明确引用实际上传的产品参考图；缺少参考图时不得签发生图或视频提交动作。

## 原生竖屏 4K 生图

分镜、尾帧和封面均直接请求原生竖屏 4K：

- 宽度：`2160px`；
- 高度：`3840px`；
- 画幅：`9:16`；
- 最大边：`3840px`；
- 两边都是 `16px` 的整数倍；
- 总像素：`8,294,400`；
- 长短边比不超过 `3:1`。

第三方 API 动作必须把 `width=2160`、`height=3840` 或供应商等价的精确尺寸参数交给宿主适配器，同时在提示词中写明原生尺寸。GPT 网页端动作必须在提示词中明确要求原生 `2160×3840` 输出。

图片验收不得再把低分辨率图片本地放大后当作合格 4K。实际宽高不等于 `2160×3840` 时直接记录失败；只有在既定图片尝试次数和剩余总预算内才可自动请求新的同渠道图片动作。任何本地格式转换都不得改变原生像素尺寸。

## 视频画面硬约束

视频提示词使用固定的连续镜头协议，覆盖完整 `0–15` 秒：

- 全程只有一个连续镜头、一个场景、同一主体构图；
- 固定中远景；
- 禁止切镜、跳切、转场、特写、突然推近、突然拉远和重新构图；
- 只允许缓慢、连续、平稳的直线跟拍或轻微固定机位运动；
- 老人从头部到双脚始终完整可见；
- 陪护者或家属的主要身体始终处于安全区；
- 整台轮椅及全部车轮始终完整位于画面安全区；
- 宁可人物在画面中稍小，也不得裁切老人腿脚、轮椅或车轮；
- 产品继续以已通过的分镜首帧和产品参考图为唯一外观依据，不在视频提示词中描述具体产品外观。

这些字段属于付费提交前的文本硬约束，不得只写在通用文档中而漏出最终 `prompt`。

## MiniMax 原生口播封闭协议

继续使用 MiniMax-H3 原生口播，不增加独立 TTS。问题控制不依赖减少总字数，而依赖封闭对白协议：

- 只能说 `script_segments` 中逐句列出的中文台词；
- 每句台词必须完整说且恰好说一次；
- 禁止重复、复述、改写、补充或延伸任何台词；
- 两名角色严格轮流说话，不得重叠或抢话；
- 当前说话者开口时，另一名角色嘴巴闭合且完全不发声；
- 非当前说话者不得出现口型、气声、附和、笑声或含混发声；
- 禁止旁白、画外音、第三人声、额外人声、哼声、伪语言、乱码语音和任何无法理解的发声；
- 除已列出的中文对白外，全片不得生成其他人声；
- 可以保留轻微环境音，不加背景音乐。

视频提示词必须按时间顺序输出封闭的说话清单，逐句绑定 `speaker_id`、角色身份、开始时间、结束时间和原文，并在清单后明确写出“清单之外零人声”。

## 免费提交前规则校验

生图和视频付费提交前增加确定性文本预检，不调用 DeepSeek 或视觉/语音模型。预检检查最终发送的提示词和动作参数，不只检查上游内容 JSON。

生图预检必须确认：

- 产品参考图是唯一依据；
- 不包含被禁止的产品外观描述；
- 精确原生尺寸为 `2160×3840`；
- 存在参考图路径；
- 第三方 API 动作携带等价的精确宽高参数。

视频预检必须确认：

- 单一连续镜头覆盖 `0–15` 秒；
- 固定中远景及禁止切镜/变焦/重构图；
- 老人头到脚、整台轮椅和全部车轮的安全区要求；
- 每个 `script_segment` 的原文和 `speaker_id` 恰好出现一次；
- 严格轮流说话、非说话者闭嘴静音；
- 禁止额外人声、伪语言、乱码语音、旁白和 BGM。

任一硬约束缺失时，不签发外部生成动作，不消耗付费预算，并把缺失字段写入项目失败记录。

## 自动模式运行流程

用户首次回复并完成预算校验后，自动执行：

```text
扫描素材
→ 查询或读取价格
→ 校验单一总预算并预留全部 V01 视频费用
→ 生成策划内容
→ 生成原生 4K 分镜、尾帧和封面
→ 图片尺寸与文件技术检查
→ 视频提示词预检
→ 提交 V01
→ 按 task_id 轮询
→ 下载视频
→ 视频技术检查
→ 按发布标题整理最终文件
→ 返回真实绝对路径并进入 WAITING_USER_FEEDBACK
```

运行中不返回图片人工审核动作、最终视频审核动作或普通“是否继续”动作。

## 视频结果与重做边界

V01 下载后不自动判断切镜、人物残缺、产品变化、口播重复、异常语言或整体观感。系统只执行确定性技术检查，并把视频交给用户查看。

- 网络、轮询或下载中断时恢复相同 `task_id`，不得新建付费任务。
- 提交是否成功不明时保留请求身份并停止，防止重复扣费。
- 文件损坏、无法解码或缺少音轨时报告技术失败，但不得自动提交 V02。
- 无论技术失败还是用户反馈的创作质量问题，都不得自动创建新的付费视频任务。
- 用户查看后主动反馈问题，系统才询问是否重做。
- 只有用户明确同意单条视频的新增费用后，才允许提交 V02；不得提交 V03。

## 状态与交付

自动模式不再要求用户先“验收通过”才能完成下载和路径交付。V01 成功下载并完成技术检查与文件整理后，批次进入 `WAITING_USER_FEEDBACK`，而不是因缺少最终人工通过而停留在 `WAITING_FINAL_REVIEW`。

每条视频必须返回：

- 视频 ID；
- 发布标题；
- 视频实际绝对路径；
- 对应项目文件夹绝对路径；
- 视频技术检查摘要；
- 本条 V01 实际费用；
- 选择第三方 API 时的本条图片实际费用；
- 状态：`V01 已下载，等待用户反馈`。

返回前必须验证：

- 路径是绝对路径；
- 视频文件真实存在；
- 文件不在临时目录；
- 视频位于对应项目的一级目录；
- 文件名来自清洗后的发布标题；
- 返回路径、技术检查候选和 SHA-256 完全一致。

最终回复不得只给批次目录、相对路径或“已完成”。本地客户端支持文件链接时，可以额外提供可点击链接，但链接目标必须是同一个真实绝对路径。

## 测试要求

所有测试离线运行，不调用 GPT 网页、第三方图片 API、DeepSeek 或 AutoDL。

1. 分镜、尾帧、封面和视频提示词都包含产品参考图唯一依据规则。
2. 最终生成提示词不包含踏板、车架、轮胎、控制器等产品外观描述。
3. 生图动作精确要求 `2160×3840`，第三方动作携带等价宽高参数。
4. 小于或不同于 `2160×3840` 的图片被拒绝，且不得通过本地放大晋升。
5. 视频提示词包含单镜头、固定中远景、人物与整车完整安全区要求。
6. 每个脚本句子和说话人恰好出现一次，并包含非说话者闭嘴静音和清单外零人声规则。
7. 缺少任一提示词硬约束时，付费动作签发失败且账本不增加。
8. 自动模式只消费一次启动输入，不产生图片或最终视频人工确认动作。
9. 首次总预算同时覆盖第三方图片 API 与全部 AutoDL V01，并优先预留 V01 视频费用。
10. V01 自动提交、轮询、下载、整理并进入 `WAITING_USER_FEEDBACK`。
11. 未经用户反馈后的新增费用授权，任何失败都不得提交 V02。
12. 轮询和下载恢复复用原 `task_id`，未知提交状态不得重提。
13. 交付结果中的视频和项目路径均为真实存在的绝对路径，并与技术证据 SHA-256 一致。
14. `learning` 模式原有确认流程不受自动模式变更影响。

## 不在本次范围

- 不增加独立 TTS 或后期配音。
- 不增加自动视觉审核、语音转写或语义质量评分。
- 不承诺生成模型绝不出现创作偏差；提示词和预检降低概率，最终质量仍由用户查看后反馈。
- 不自动批准或提交 V02。
- 不改变第三方 API 密钥的安全存储规则。
- 不生成新版本号或完整技能发布 ZIP，直至用户另行要求。
