# 节点产出显式验收晋升 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 只有与用户明确 `passed` 事件哈希一致的节点产出才能出现在单条任务第一级，无证据、失败或撤销的文件自动安全归档。

**Architecture:** 在现有便携单文件 `workflow_cli.py` 内增加验收事件存储、哈希校验、原子晋升和严格审计，保持跨 Agent 复制后无需 Python 包安装的运行方式。整理单条或批次目录时先执行产出审计，再整理过程文件；五项产出彼此独立，旧 Markdown/JSON 记录只供查阅，不自动转换为通过事件。

**Tech Stack:** Python 3.9、`pathlib`、`hashlib`、`json`、`uuid`、`shutil`、pytest、Markdown Agent Skill 规则。

## Global Constraints

- 五项产出固定为 `标题.txt`、`发布正文.md`、`分镜图.png`、`封面图.png`、`视频.mp4`。
- 只有用户明确反馈形成的 `passed` 事件才能晋升。
- 验收事件必须绑定候选相对路径和 SHA-256。
- 自动检查通过、技术指标通过、等待人工验收和旧格式验收结果都不能自动晋升。
- 没有有效通过事件的节点，一级目录缺少对应文件。
- 旧产出、失败产出、待验收产出和被替换产出均归档，不删除、不覆盖。
- 不重新生成任何内容，不调用 AutoDL，不产生费用。
