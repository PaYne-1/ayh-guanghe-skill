# 批量验收与经验学习

## 自动验收材料

每条视频生成：

```text
_工作文件/生成过程/视频候选.mp4
_工作文件/验收记录/验收预览图.jpg
_工作文件/验收记录/自动验收报告.md
_工作文件/生成过程/语音转写.txt
```

自动检查产品与 Logo、人物数量/身份/性别、单镜头、动作限制、字幕、对白、说话人、嘴型、改善益处、购买引导、背景音乐和正式历史规则。自动结果只提供证据，不替用户做最终决定。

自动验收是必要前置证据，但不能代替用户明确通过，也不能触发最终晋升。只有 `review-output` 针对具体候选文件写入用户确认、候选相对路径和 SHA-256 后，`passed` 文件才能成为一级 `视频.mp4`；没有明确通过时一级目录不保留视频。

单镜头连续性、运镜稳定性和口播完整性是硬失败项。验收必须检查全片而不只检查首尾帧，并在报告中标注异常时间点：出现切镜、跳切、转场、突然改变景别、人物出框、产品角度或构图明显漂移时，自动判为不合格；语音转写发现漏词、改词、加速抢读或尾句被截断，导致唯一卖点、使用改善或结尾引导未完整表达时，也自动判为不合格。

对话式脚本还必须自动核验每个 `script_segments[].speaker_id` 是否由对应人物音色说出。两个或以上说话人使用同一音色、人物替别人说台词、说话顺序颠倒、音色身份与人物清单不符，或出现老人自问自答等情况，均为说话人硬失败项；不能因为台词文本齐全、音轨未截断或波形完整而判为通过。此项由系统逐段验收，不增加用户试听确认节点。

合理尾帧首尾帧模式中，真实直线行驶产生的自然视角变化、轻微亮度波动或连续插值过渡必须在报告中记录时间点并进入复核，不得单独自动判为硬失败。切镜、人物裁切、产品结构变形、轮椅未真实行驶、角色自问自答、台词串角色、语音不可理解或缺少下单类行动指令仍为硬失败。用户明确验收结论为最终状态；自动报告和异常时间点继续保留自动检查证据，不得删除或改写为未发生。

## 批量验收

```powershell
python scripts/workflow_cli.py build-review --batch "产品文件夹/生成视频/批次目录"
```

打开 `批次验收报告.html`。每条卡片选择“通过”或“不通过”；不通过必须写原因，可以写修改建议。点击“完成验收”下载 `批次验收结果.json`，再回写：

```powershell
python scripts/workflow_cli.py record-review `
  --batch "批次目录" `
  --result "下载的批次验收结果.json"
```

脚本生成批次 JSON/Markdown、每条 `_工作文件/验收记录/人工验收结果.md`，并把失败项写入候选经验。所有自动或人工验收证据都进入 `_工作文件/验收记录`，不占用单条任务第一级。

旧格式批次结果不包含候选路径和 SHA-256 时不能自动转换为 `passed`。用户明确通过后执行 `workflow_cli.py review-output`；任务结束或整理时执行 `workflow_cli.py audit-outputs`，撤下无证据、失败、撤销或哈希不一致的一级文件。

## 一次重跑

问题按以下节点分流：

| 问题 | 返回节点 |
|---|---|
| 痛点、脚本、人物、标题错误 | 内容策划 |
| 产品外观、Logo、人物图错误 | 分镜图 |
| 正文错误 | 发布正文 |
| 动作、对白、嘴型、视频提示词错误 | 视频提示词与提交 |
| API、轮询或下载错误 | 技术恢复，不改创作内容 |
| 模型无法稳定完成 | 改用更稳定表达，并记录模型能力边界 |

每条只保留 `V01_初次生成` 和 `V02_唯一一次重跑`。V02 仍不通过，标记人工专项处理，不发起第三次付费任务。

## 学习规则

- 用户反馈和首次失败只形成候选经验。
- 重跑通过说明修改可能有效，但学习模式仍要用户确认后才能升级正式规则。
- 重跑仍失败时记录为 MiniMax-H3 或对应模型能力边界，不把失败方案升级。
- 自动模式只读取正式规则；新候选不能自动污染正式库。
- 卖点库按产品独立保存；不保存标题库、脚本库或分镜库。
