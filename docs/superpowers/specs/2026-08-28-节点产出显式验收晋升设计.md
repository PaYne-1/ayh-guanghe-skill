# 产品视频节点产出显式验收晋升设计

## 目标

单条产品视频任务目录第一级只保存经过用户明确验收通过的最终产出。固定文件名、最新修改时间、自动检查通过、技术指标通过或“等待人工验收”均不能单独证明产出有效。

## 五项独立产出

以下五项分别建立独立验收门槛：

- `标题.txt`
- `发布正文.md`
- `分镜图.png`
- `封面图.png`
- `视频.mp4`

每项可以独立通过或失败。某一项失败不得撤销其他已经明确通过且哈希未变化的产出。

## 验收证据

验收记录保存在：

`_工作文件/验收记录/产出验收记录.json`

记录采用只追加事件结构，每条事件必须包含：

- `artifact_name`：五个固定产出名之一；
- `source_path`：被验收候选文件在单条任务目录内的相对路径；
- `sha256`：候选文件内容的 SHA-256；
- `decision`：`passed`、`failed` 或 `revoked`；
- `confirmed_by`：明确确认人；
- `confirmed_at`：带时区的 ISO 8601 时间；
- `feedback`：通过说明、失败原因或撤销原因；
- `event_id`：唯一事件标识。

同一产出和哈希存在多条事件时，以 `confirmed_at` 和记录顺序确定的最后一条事件为准。只有最后事件为 `passed` 才能晋升。

自动验收程序可以生成候选结论，但不得写入 `confirmed_by` 为用户的 `passed` 事件。只有用户明确反馈通过，或用户明确授权的人工验收结果导入，才算最终通过。

## 晋升规则

提供独立的产出验收与晋升命令。命令接收单条任务目录、固定产出名、候选源文件、决定、确认人和反馈。

当决定为 `passed` 时：

1. 候选源文件必须位于该单条任务目录内，不能引用外部路径。
2. 计算并记录候选文件哈希。
3. 写入验收事件。
4. 若第一级已有同名且不同哈希文件，先移动到 `_工作文件/历史版本/已撤换产出/`，不得覆盖或删除。
5. 以临时文件复制候选，再原子替换为第一级固定文件名。
6. 重新计算一级文件哈希，必须与通过事件完全一致。

当决定为 `failed` 或 `revoked` 时，只记录事件，不晋升候选。如果第一级同名文件的哈希正好等于该失败或撤销事件的哈希，则把一级文件移入 `_工作文件/历史版本/未通过或待验收/`。

禁止直接把候选文件手工改名为五个固定产出名来绕过验收记录。

## 一级目录审计

整理命令和单独的审计命令都必须校验五项一级文件：

1. 计算一级文件哈希。
2. 查找同一 `artifact_name + sha256` 的最后一条验收事件。
3. 最后事件为 `passed` 时保留。
4. 没有事件、事件为 `failed`、事件为 `revoked`、记录损坏或哈希不一致时，移动到 `_工作文件/历史版本/未通过或待验收/`。
5. 审计报告列出 `promoted`、`valid`、`demoted`、`missing` 和 `errors`，并包含每项的证据事件。

任何错误都不得通过删除、覆盖或猜测解决。发生目标同名冲突时，使用带时间和短哈希的唯一归档名保留所有版本。

## 工作流接入

- 内容节点产生标题和正文候选，但只有用户分别明确通过后，`标题.txt` 和 `发布正文.md` 才出现在一级目录。
- 分镜节点的最终候选只有明确通过后才晋升 `分镜图.png`。
- 封面节点的最终候选只有明确通过后才晋升 `封面图.png`。
- 视频节点必须先通过自动硬规则，再由用户明确最终通过，之后才晋升 `视频.mp4`。
- 批次验收结果中的 `decision: passed` 只能晋升它明确绑定的候选视频哈希；旧格式中没有候选路径和哈希的结果不得自动晋升。

后续节点读取前一级产出时，也必须校验对应的 `passed` 事件和哈希，不能仅检查固定文件是否存在。

## 现有任务迁移

对现有任务首次执行严格审计时，不补造历史通过记录，也不根据报告措辞猜测：

- 一级 `视频.mp4` 与已明确人工判定失败的 V01 同哈希，必须撤下并归档。
- 其余一级产出没有绑定具体文件哈希的明确通过事件，也必须先撤下并归档。
- 五项候选仍完整保存在 `_工作文件`，等待用户逐项明确确认后再晋升。

本次处理不重新生成图片、文案或视频，不调用付费 API。

## 向后兼容

旧的 Markdown 和批次 JSON 验收记录继续保留用于人工查阅，但不能直接作为晋升依据。只有通过显式导入流程绑定具体候选文件并由用户确认，才能转换为新验收事件。

读取一级产出的脚本必须拒绝无有效通过事件的文件，并返回清晰错误，指出缺少验收证据、哈希不匹配或最新事件不是 `passed`。

## 验证标准

- 没有验收记录的候选不能出现在一级目录。
- 自动结论为通过但没有用户明确通过时不能晋升。
- `passed` 事件绑定的候选能原子晋升，一级哈希与事件一致。
- `failed` 或 `revoked` 的同哈希一级文件会安全撤下。
- 后续修改候选内容导致哈希变化时，旧通过事件不能授权新文件。
- 替换已通过产出前会归档旧一级文件，不删除任何版本。
- 重复执行审计结果幂等，不产生重复归档。
- 旧格式验收记录不会被误判为新格式明确通过。
- 批次整理只审计每个 `VNNN_` 子任务，不移动批次级文件。
- 当前示例任务严格审计后，一级五项产出全部撤下，且原文件均可在历史归档中恢复。

## 不在本次范围

- 不替用户判断候选内容是否合格。
- 不自动把任何旧报告转换为 `passed`。
- 不重新提交 AutoDL 或产生费用。
- 不删除失败、待验收或已撤换版本。
