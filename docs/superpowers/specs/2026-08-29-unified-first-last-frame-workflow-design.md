# 产品视频统一首尾帧工作流设计

## 目标

把产品短视频流水线统一为行驶中的双人对话场景。每条视频固定生成一张正式分镜图作为首帧，再独立生成一张合理尾帧图，最后使用 MiniMax H3 首尾帧工作流生成视频。

## 统一执行契约

每条任务必须满足以下结构：

1. 场景为轮椅真实向前行驶，老人和一名陪护者或家属进行双人对话。
2. 生成一张 `2160×3840`、`9:16` 的正式分镜候选；用户明确通过后晋升为一级 `分镜图.png`，并作为视频首帧。
3. 依据已通过分镜独立生成一张同尺寸合理尾帧，保存到 `_工作文件/生成过程`，不得复用首帧，也不作为第二张正式分镜交付。
4. 尾帧表现主体继续向前约 1–1.5 米后的连续状态，包括合理的背景透视后移、车轮转动和陪护者下一步步态，同时保持产品结构、人物比例、主体屏幕位置、安全边距和整体影调一致。
5. 尾帧通过尺寸、主体完整度、产品结构和首尾一致性检查后，使用 `minimax_h3_lightx2v` 首尾帧模式生成 15 秒视频。
6. 视频提示词必须把“一镜到底、连续平稳运镜、完整双人对话口播”声明为覆盖 0–15 秒全程的硬规则。

## 删除的分支

- 不再根据场景判断是否命中首尾帧模式。
- 不再把 `minimax_h3_image_audio_to_video_v2_15s` 作为新视频默认路径。
- 不再允许普通单人、静止展示或非双人对话场景进入本工作流。
- 启动确认单中的“是否命中行驶双人对话合理尾帧模式”改为固定规则，不提供“否”的选项。

## 文件和交付边界

一级交付目录仍只保留 `视频.mp4`、`封面图.png`、`发布正文.md`、`标题.txt`、`分镜图.png` 和 `_工作文件`。合理尾帧是视频生成过程资产，必须记录候选路径、SHA-256 和结构检查结果，但不晋升为第二张 `分镜图.png`。

## 错误处理

- 正式分镜最多尝试三次；第三次仍不合格时只暂停该项目。
- 合理尾帧不合格时不得提交付费视频任务，应重新生成或暂停该项目。
- 首尾帧缺失、尺寸错误、哈希缺失、产品结构不一致或视频工作流不是 `minimax_h3_lightx2v` 时，付费前检查必须失败。
- AutoDL 返回未知提交状态时不得盲目重提；预算和付费授权边界保持不变。

## 验证标准

1. 全包搜索不存在“其他场景继续使用现有工作流”“命中时”“是 / 否”等条件式首尾帧表述。
2. 所有入口文档一致声明：一张正式分镜首帧、一张独立合理尾帧、一个首尾帧视频。
3. 启动确认和付费前检查能够拒绝缺少合理尾帧证据的任务。
4. 自动测试通过，技能目录快速校验通过。
5. 可分发目录与本机已安装副本的受控文件内容一致。
