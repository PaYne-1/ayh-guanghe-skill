# 合理尾帧行驶对话规则 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已验收的“合理 4K 尾帧 + MiniMax H3 首尾帧”流程固化为行驶双人对话场景的优先规则，并规范可变家属角色、对话结构和下单类结尾指令。

**Architecture:** 本次只修改可移植技能包的 Markdown 行为契约及其规则测试，不新增应用、服务或付费调用代码。仓库中的技能包是规则源，测试通过后以相同内容同步到 `C:\Users\Administrator\.agents\skills\product-video-pipeline`，再分别验证源码包和已安装包。

**Tech Stack:** Markdown、Python 3、pytest、Codex skill `quick_validate.py`

## Global Constraints

- 仅修改规则与规则测试，不开发完整应用，不提交任何付费视频任务。
- 行驶、双人对话、需要保持通过分镜构图时，优先使用 `minimax_h3_lightx2v` 合理尾帧首尾帧方案；其他场景继续按现有路由。
- 陪护者身份不得固定为女儿，可为儿子、女儿、孙子、孙女、配偶、护理人员或其他合理角色。
- 对话结构固定为“陪护者提问 → 老人回答卖点 → 明确下单类行动指令”，但具体人物关系和文案不得写死。
- 首帧和尾帧默认均为 2160×3840；尾帧是独立生成的合理前进行驶状态，不得复用首帧。
- 自然视角变化和轻微亮度波动进入复核，不单独自动判硬失败；切镜、裁切、产品变形、自问自答、口播缺失和缺少下单 CTA 仍是硬失败。
- 用户明确验收结论是最终状态，自动检查证据必须保留。
- 保留工作区中所有已有改动；由于目标文件已有未提交修改，不把混合改动提交到 Git。
