# 交互与最终交付契约

## 自动 V01 交付

自动模式从首次回复的授权开始，在本批次最高总预算内连续执行内容、已锁定生图渠道的三张原生 4K 图片和 V01。图片不设置人工审核节点，也不进行模型视觉审核；V01 也不设置自动语义审核。技术检查通过即返回 `V01_DELIVERED`，状态 `WAITING_USER_FEEDBACK`。

每个交付行必须包含：

```json
{
  "video_id": "V001",
  "video_path": "真实存在的绝对路径",
  "item_dir": "真实存在的绝对路径",
  "sha256": "候选和交付文件一致的 SHA-256",
  "technical": {"ok": true, "full_decode": true},
  "video_cost_yuan": "V01 成本",
  "image_cost_yuan": "图片成本",
  "status": "V01 已下载，等待用户反馈"
}
```

运行器必须重新解析、验证文件存在且为绝对路径，验证其不在临时目录、位于对应项目一级目录，并把相同数据写入 `批次V01交付.json`。Windows 路径以正斜杠展示，含空格时使用尖括号。没有通过这些检查不得交付。

## 用户反馈和 V02

V01 的语义缺陷不由系统自动判断。只有用户在 `WAITING_USER_FEEDBACK` 提出反馈后才使用 `request-rerun` 记录问题；该命令不付费、不归档 V01、不增加重跑次数。之后必须显式批准该视频的 V02 费用；V02 完成后进入人工验收，禁止自动 V03。

## 图片和产品参考

分镜、尾帧、封面均为**原生2160×3840**；禁止本地放大、裁切、拉伸、补画和重绘。所有生成上下文都声明**产品参考图是唯一产品依据**，禁止用文字重新描述产品外观。图片技术通过后自动晋升，仍保留 SHA-256 与候选路径。

## 七项最终产出

一级目录只保留 `标题.txt`、`发布正文.txt`、`话题标签.txt`、`分镜图.png`、`尾帧图.png`、`封面图.png`、按发布标题清洗命名的 MP4 和 `_工作文件`。每个一级产出都必须有匹配的 SHA-256 和通过事件。自动 V01 交付仅表示等待反馈；学习模式或 V02 的最终完成仍需七项最终产出全部有效。

## 人工反馈定位知识（不得注入生成提示词）

交付问题可使用路径、哈希、时间点和参考图定位；不得把任何产品组件或外观事实回填至分镜、尾帧、封面或视频提示词。
