# AutoDL.Art MiniMax-H3

## 固定参数

```text
默认新视频工作流 ID：`minimax_h3_lightx2v_v5_15s`

AutoDL 凭据使用 `python scripts/api_config.py configure --category autodl` 永久配置到 Windows 当前用户环境变量。运行器优先读取当前进程环境，缺失时读取当前用户持久环境；状态输出只显示密钥末四位。
兼容工作流别名：`minimax_h3_lightx2v`
时长：15 秒；比例：9:16；分辨率：768P 或启动时确认的 2K
首尾帧：first_frame、last_frame；声音：封闭双角色原生音轨，无 BGM
```

`first_frame` 和 `last_frame` 必须分别是已验收的**渠道支持的原生分辨率**文件，且 SHA-256 不同；禁止本地放大。提交时按当前 API 映射为参考图字段，图片路径不直接上传为本地文件路径。

`prompt` 由合同编译，必须覆盖完整 0–15 秒：一个连续镜头、**固定中远景**、完整人物和产品安全区。每句台词绑定 `speaker_id` 并仅出现一次；**非当前说话者嘴巴闭合且完全不发声**；**清单之外零人声**，无画外音、重复、发明声音或 BGM。首尾帧只加强端点约束，不放宽全过程规则。

提交前保存 `_工作文件/任务状态/提交请求.json` 和请求哈希；先 dry-run，再在 V01 封存预算内提交。响应成功立即保存 `task_id`；不确定时只查询原任务。

自动 V01 完成技术检查后交付 `V01_DELIVERED`/`WAITING_USER_FEEDBACK`，返回真实存在的绝对路径，不做语义验收。用户反馈后的 V02 必须显式费用批准。

## 视频轮询时序

收到提交成功的task_id后，首次状态查询等待300秒（5分钟）；若未完成，之后每次查询间隔60秒（1分钟）。以任务状态文件的next_poll_at为准，重启或重复调用不重置首次等待，不提前查询，不重新提交。多条视频各自计时，按最近到期时间唤醒。等待期间可报告本地倒计时，但不要为刷新进度额外请求API。单次查询超时仍为20秒。

旧policy/profile中的poll_interval_seconds仅保留历史批次摘要兼容；当前运行器统一执行上述300/60秒规则。旧任务没有首次计时记录时沿用已有任务继续查询，不虚构提交时间或重新等待5分钟。

## 视频尺寸验收与恢复

768P（含别名768p竖）接受768×1365或768×1344；后者是允许的工作流输出尺寸，不宣称严格9:16。2K仍要求1440×2560。按实际像素记录交付证据，不拉伸、裁剪或放大视频以满足校验。此兼容仅用于输出视频，不改变输入图片的原生9:16要求。

若已有视频仅因旧尺寸规则被拒绝，保留原task_id和费用台账，使用现有候选重新执行技术验收；不得因该问题重新提交付费生成。音轨、13–17秒时长、全片解码及其他交付检查照常执行。

## 人工反馈定位知识（不得注入生成提示词）

人工可比对参考图、首尾帧、候选和哈希以定位问题；不得将任何产品外观或组件细节写入 AutoDL `prompt`。
