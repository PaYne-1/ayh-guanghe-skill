# 跨智能体首尾帧与封面底图生图规则

## 适用范围

本文件适用于产品短视频流水线中的正式分镜首帧、独立合理尾帧和封面底图生成节点，可由 Codex、WorkBuddy、Hermes 或其他具备 Windows 应用控制、浏览器控制或第三方 API 调用能力的智能体独立执行。

本文件是强制执行契约。生图固定路由为：

`本机 Codex 界面 → ChatGPT 网页端 → 第三方 API 生图`

不得调用当前智能体自身的原生生图能力。不得跳级、并行调用多个渠道或自行改变优先顺序。

## 启动前置条件

进入生图节点前，必须从本批次启动确认单读取并核对：

- 产品名称、产品图片路径和本条视频 ID；
- 分镜提示词、合理尾帧提示词或封面底图提示词；
- 固定目标尺寸 `2160×3840`、画幅 `9:16`；
- 本机 Codex 是否已安装、登录且允许控制；
- ChatGPT 网页端是否已登录且允许控制；
- 第三方 API 名称、模型、密钥环境变量、单张价格和生图预算；
- 图片用途；合理尾帧还必须读取已通过正式分镜的路径和 SHA-256；
- 本条图片候选路径和每个图片用途最多三个有效候选的限制。

缺少产品参考图、提示词或输出目录时，不得开始生图。不得因生图而修改原始产品图片。

## 通用生图请求包

三个渠道必须使用同一份请求包，不得在切换渠道时擅自改变人物、场景、卖点或产品结构。请求包至少包含：

```text
视频 ID：
图片用途：正式分镜首帧 / 独立合理尾帧 / 封面底图
产品名称：
主参考图：合理尾帧必须以已通过正式分镜为主参考；其他用途按节点选择
辅助参考图：
完整提示词：
必须保持：产品结构、颜色、Logo、人物身份与数量、主体构图
禁止出现：额外产品、错误 Logo、结构变形、人物增减、无关文字、水印
目标尺寸：2160×3840
目标画幅：9:16
候选输出路径：_工作文件/生成过程/分镜候选.png 或 _工作文件/生成过程/合理尾帧候选.png
```

封面底图不得让生图模型绘制最终中文标题；最终文字继续由既有封面渲染流程确定性绘制。

## 路由一：本机 Codex 界面

当前智能体必须首先尝试操作本机 Codex 界面：

1. 打开本机 Codex，并新建独立任务，避免污染已有任务上下文。
2. 上传请求包列出的主参考图和辅助参考图。
3. 完整提交提示词、保持项、禁止项、目标尺寸和画幅。
4. 等待生成结束，检查界面确实返回完整图片而非占位图或错误消息。
5. 取得实际原始图片文件，并复制到本条任务的 `_工作文件/生成过程`。

界面预览、截图、缩略图或聊天中的图片占位符不能作为候选文件。必须取得可以在文件系统中读取的原始图片。

出现以下任一情况时，记录失败证据并进入 ChatGPT 网页端：

- Codex 未安装、未登录、无法打开或无法控制；
- 生图能力不可用、任务报错或等待超时；
- 没有取得实际图片文件；
- 生成图片未通过本文件规定的技术检查或视觉检查。

## 路由二：ChatGPT 网页端

本机 Codex 路由失败后，允许通过浏览器控制已登录的 ChatGPT 网页端：

1. 打开 ChatGPT 并新建独立对话。
2. 上传与 Codex 路由完全相同的产品参考图。
3. 提交同一份请求包，不得删除保持项、禁止项、尺寸或画幅要求。
4. 等待图片生成完成，使用网页提供的原图下载能力保存文件。
5. 将下载的原始图片复制到本条任务的 `_工作文件/生成过程`。

不得使用浏览器截图、页面截图或预览缩略图代替下载的原始图片。

不得要求用户提供账号密码，不得读取、记录、保存或转发登录凭据。遇到登录、验证码、二次验证、安全确认或需要用户处理的订阅限制时，暂停界面操作并让用户完成该步骤；智能体不得尝试绕过。

出现以下任一情况时，记录失败证据并进入第三方 API：

- ChatGPT 未登录、无法访问、达到使用限制或无法控制；
- 生成报错、等待超时或无法下载原图；
- 下载文件损坏或不是实际图片；
- 生成图片未通过技术检查或视觉检查。

## 路由三：第三方 API 生图

只有 Codex 和 ChatGPT 两个路由均失败后，才允许调用启动确认单中已经配置的第三方生图 API。

1. 从本机环境变量或受保护配置读取密钥，不得要求用户在聊天中粘贴完整密钥。
2. 正式调用前执行 dry-run，验证模型、参数、参考图、输出目录和预算。
3. 只有用户已经批准该 API、实时单价和本批次生图预算时，才能正式付费提交。
4. 保存请求参数、请求哈希、提交时间、任务 ID、费用和原始响应。
5. 下载结果到临时文件，确认完整后再原子移动为候选文件。
6. 未知提交状态不得盲目重提；先使用任务 ID 或请求哈希查询。

第三方 API 未配置、鉴权失败、余额不足、预算超限或生成结果仍不合格时，停止当前项目，不得继续产生付费任务。批次内其他项目继续执行。

## 候选次数与切换规则

每个图片用途最多产生三个有效候选：

1. 第一个有效候选来自本机 Codex；
2. 第二个有效候选来自 ChatGPT 网页端；
3. 第三个有效候选来自第三方 API。

只有实际产生并成功落盘的图片才计为有效候选。应用打不开、登录失效、网页不可访问、API 鉴权失败等未产生图片的技术失败不占用有效候选次数，但必须记录失败原因并立即进入下一路由，不得在同一路由无限重试。

每次写入新的同名候选前，必须把旧候选移动到 `_工作文件/历史版本/候选版本`，不得覆盖或删除旧候选及其验收证据。

第三个候选仍不合格时：

- 将当前项目标记为“需要人工处理”；
- 保存三个渠道的失败原因、候选路径、提示词和检查结果；
- 不再生成第四个候选，不再调用任何付费生图接口；
- 继续批次内其他项目。

## 统一技术检查

任何渠道生成的图片都必须执行相同检查：

- 文件真实存在、大小非零且能够解码；
- 文件为允许的图片格式，不是 HTML、错误响应、截图或占位文件；
- 实际像素尺寸为 `2160×3840`；
- 实际画幅为 `9:16`；
- 计算并记录 SHA-256；
- 候选路径位于当前任务 `_工作文件/生成过程`；
- 历史候选与失败证据已经归档。

尺寸或画幅不符合要求时，不得通过拉伸图片伪装合格。允许在不改变构图和主体完整度的前提下使用确定性等比缩放；需要裁切、补画或重新构图时，必须作为新的生图候选处理。

## 统一视觉检查

技术检查通过后继续检查：

- 产品结构、轮廓、颜色、材质和 Logo 与参考图一致；
- 不得增加、删除或替换关键产品部件；
- 人物身份、性别、数量、服装、动作和相互关系符合内容契约；
- 场景、卖点和镜头构图符合本条脚本；
- 产品和人物主体完整，不得被意外裁切；
- 无错误文字、无关品牌、平台水印或额外商品；
- 分镜图能够作为后续视频的首帧视觉基准。
- 合理尾帧以已通过分镜为主要视觉基准，表现主体继续直线前进约 1–1.5 米；背景透视、车轮转动和陪护者步态合理演进，人物数量、产品结构、构图尺度、安全边距和整体影调与首帧一致，且文件内容不得与首帧相同。

自动视觉判断只能形成验收证据，不能代替用户明确验收。

## 落盘与验收

分镜候选统一保存为：

```text
_工作文件/生成过程/分镜候选.png
```

独立合理尾帧候选统一保存为：

```text
_工作文件/生成过程/合理尾帧候选.png
```

封面底图候选统一保存到 `_工作文件/生成过程`，使用现有封面节点约定的候选文件名。

同时在 `_工作文件/验收记录` 保存：

- 使用的渠道；
- 请求包和最终提示词；
- 原始下载路径或 API 任务信息；
- 技术检查结果；
- 视觉检查结果；
- 候选相对路径和 SHA-256；
- 失败原因与下一路由决定。

正式分镜只有在用户针对当前候选明确选择“通过”，并由 `review-output` 绑定候选路径和 SHA-256 后，才能晋升为一级 `分镜图.png`。合理尾帧只保存为过程资产，不晋升为第二张一级分镜；它必须绑定已通过首帧哈希并通过尺寸、主体完整度、产品结构和首尾视觉一致性检查。界面显示成功、文件下载完成或第三方 API 返回成功，都不能单独使任一候选进入后续视频节点。

## 完成条件

生图节点只有在以下全部条件满足时才算完成：

1. 候选原始文件已经落入当前任务目录；
2. 技术检查通过；
3. 视觉检查通过并保留证据；
4. 正式分镜已由用户明确通过，验收事件绑定相同候选路径和 SHA-256，晋升后再次校验哈希一致；
5. 合理尾帧已绑定正式分镜哈希，记录自身路径和 SHA-256，并通过首尾一致性检查；
6. 封面底图按既有封面验收规则处理。

任何一项未满足时，后续节点不得仅凭文件存在继续执行。
