# 跨 Agent 产品视频生成技能包设计

- 日期：2026-08-26
- 状态：已完成逐项确认，等待用户审核书面规范
- 现有项目：`D:\0-AI 项目\ayh-h3`
- 首个产品品类：爱优护电动轮椅
- 技术方案：通用 Python 核心 + Agent 适配器 + 本地批量验收页面

## 1. 目标

把现有面向爱优护电动轮椅的零散提示词和 AutoDL.Art 生成脚本，改造成可由 Codex、WorkBuddy、Hermes 及其他 Agent 共同使用的跨平台技能包。

技能包接收任意产品图片文件夹、用户本次提供的卖点和计划视频数量，自动完成策划、分镜图、封面图、发布正文、MiniMax-H3 视频生成、下载、批量验收、修改重跑和经验复盘。

核心业务流程固定为：

1. 准备产品参考图。
2. 根据卖点分析适用人群、场景、痛点、切入角度和选题，生成脚本、标题、封面标题、分镜图提示词和视频提示词。
3. 根据分镜图提示词生成唯一分镜图，并生成封面图。
4. 根据最终脚本和分镜图生成视频发布正文。
5. 配置 MiniMax-H3 视频参数和预算。
6. 提交 AutoDL.Art 视频任务。
7. 获取并持久化 `task_id`。
8. 定时查询生成状态。
9. 下载并校验 MP4。
10. 通过批量验收页面完成人工验收。
11. 对不合格视频复盘、修改并最多重跑一次。

## 2. 设计原则

1. **跨 Agent**：业务逻辑不绑定 Codex。不同 Agent 的入口文件只负责启动通用 Python 核心。
2. **配置前置**：正式任务开始前一次性确认全部参数，运行中不临时询问普通配置。
3. **按条隔离**：一条视频失败、超时或待人工处理，不阻塞同批次其他任务。
4. **可恢复**：每次状态变化立即落盘，中断后从最后一个完整节点继续。
5. **防重复扣费**：已经取得 `task_id` 或存在同批次请求哈希的任务不重复提交。
6. **单卖点原则**：一条视频只围绕一个核心痛点和一个产品卖点。
7. **规则学习而非脚本复用**：沉淀卖点、规范、错误原因和有效规避方法；不沉淀具体脚本分镜库。
8. **凭据安全**：API 密钥只从环境变量或 Agent 安全凭据读取，不写入技能包、日志或任务输出。

## 3. 方案选择

### 3.1 已选方案

采用“通用 Python 核心 + Agent 适配器 + 本地批量验收页面”。

```text
Codex / WorkBuddy / Hermes / 其他 Agent
                  ↓
            平台入口适配器
                  ↓
          通用 Python 工作流引擎
        ┌─────────┼─────────┐
        ↓         ↓         ↓
     规则系统   任务状态机   模型适配器
        ↓         ↓         ↓
   经验与卖点库  项目文件   文本/生图/H3
                  ↓
          本地批量验收页面
```

### 3.2 不选的方案

- 不采用只有 `SKILL.md` 和零散脚本的轻量方案，因为状态恢复、批量隔离、费用控制和验收一致性不足。
- 不采用完整常驻 Web 系统，因为部署、权限、数据库和维护成本超出第一版需要。

- 重跑前学习模式下的统一修改方案和费用确认。

## 6. 产品素材与产品身份

1. 每次任务由用户提供任意产品文件夹路径，不设置固定产品目录。
2. 产品名称默认取路径最后一级文件夹名，允许用户在启动确认单中覆盖正式名称。
3. 只读取产品文件夹第一层的 PNG、JPG、JPEG、WEBP 等图片，不递归扫描子文件夹。
4. 不移动、不修改产品原图。
5. `生成视频` 子文件夹被自动忽略。
6. 每个产品独立维护卖点库。产品卖点不跨产品合并。

产品卖点库至少记录：

- 产品名称和内部标识；
- 最近使用的产品路径；
- 卖点分类与内容；
- 首次使用时间、最近使用时间和使用次数。

用户本次提供的卖点直接使用，不做二次选择确认。使用过的卖点去重后沉淀到对应产品卖点库。

### 6.1 通用核心与产品内容配置

Python 工作流核心不写死爱优护、电动轮椅或固定话题。每个产品使用独立的内容配置，至少包含：

- 产品正式名称、品类和品牌称呼；
- 发布平台和内容类型；
- 发布标题必须包含的品类词；
- 结尾对话使用的产品称呼；
- 固定话题标签；
- 产品或品类专属动作限制；
- 产品外观、Logo 和禁用表达；
- 当前适用的人设和提示词规范版本。

本设计第 9 至 12 节确认的“电动轮椅”“爱优护电动轮椅”、固定话题和直线/折叠规则，属于首个 `爱优护电动轮椅_淘宝天猫光合` 内容配置，不是所有产品的全局默认值。

未来处理其他产品时，技能在任务启动阶段加载对应产品配置；不存在配置时，必须在启动确认单中一次性收集必要的品类词、品牌称呼、发布平台和内容规则，不能把爱优护配置套到其他产品。

规则优先级固定为：

```text
本次任务明确要求
> 产品专属规则
> 品类专属规则
> 已验证经验
> 通用默认规范
```

## 7. 数量分配

1. 一个卖点对应一条独立视频，不把多个卖点合并进同一条。
2. 用户提供卖点清单和计划视频总数。
3. 总数平均分配给各卖点。
4. 不能整除时，余数按卖点顺序从前往后分配。
5. 例如 5 个卖点生成 25 条，则每个卖点 5 条；5 个卖点生成 23 条，则分配为 5、5、5、4、4。
6. 同一卖点生成多条时，至少改变适用人群、使用场景、核心痛点、切入角度或选题方向，避免内容同质化。
7. 每个卖点默认生成 1 套方案；用户可在启动时指定每个卖点生成 3 套或更多方案。

## 8. 双运行模式

### 8.1 学习确认模式

- 节点 2 内容完成后暂停，等待用户审核。
- 节点 3 分镜图和封面图完成后暂停，等待用户审核。
- 用户修改反馈进入复盘系统，先形成候选经验。
- 最终视频始终进行批量人工验收。
- 不合格视频的修改方案和费用在批次级别统一确认后重跑。

### 8.2 自动生产模式

- 节点 2 和节点 3 由规则及历史经验自主检查并继续。
- 单条任务失败后只进入失败队列。
- 在启动时确认的最高预算内，可自动修改并重跑一次。
- 最终视频仍统一人工验收。

每次新任务都必须重新询问运行模式，不沿用上一次选择。

## 9. 节点 2：内容策划

本节标题、品牌、结尾和电动轮椅动作要求是 `爱优护电动轮椅_淘宝天猫光合` 内容配置的当前规则。通用引擎从产品配置读取对应字段。

### 9.1 策划过程

每条视频根据产品图片、单个卖点、任务人设、产品规则和经验规则，依次生成：

```text
适用人群
→ 使用场景
→ 核心问题痛点
→ 卖点切入角度
→ 选题方向
→ 人物清单
→ 15 秒单镜头脚本
```

不分析或编造疾病、伤情、治疗及康复信息。只使用“老人、行动不便人群、家属照护者”等宽泛且与任务相关的人群描述。

### 9.2 每条视频输出

1. 基础信息：视频编号、产品、唯一卖点和方案编号。
2. 视频核心创意。
3. 策划分析：适用人群、使用场景、核心痛点、对应卖点、切入角度、选题方向和预期感受。
4. 一个视频发布标题。
5. 一个视频封面标题。
6. 人物清单和结尾说话角色。
7. 15 秒视频脚本。
8. 一个唯一分镜图提示词。
9. 一个对应的视频生成提示词。
10. 最终成片感觉。
11. 真人实拍建议。
12. 自动检查报告。

### 9.3 视频发布标题

- 每条只生成 1 个。
- 约 20 个汉字。
- 必须完整包含“电动轮椅”。
- 不强制包含“爱优护”。
- 使用标题党式钩子，但语义必须顺畅。
- 围绕当前痛点和唯一卖点制造好奇、反差、疑问或结果感。
- 不编造参数，不使用绝对化、夸张或违规承诺。
- 只用于发布，不进入视频画面。

### 9.4 封面标题

- 每条只生成 1 个。
- 约 5 个汉字，允许 4 至 6 字。
- 根据视频发布标题和核心痛点提炼。
- 不强制包含“电动轮椅”。
- 优先突出痛点、改善结果、反差或悬念。
- 不写入分镜图和视频画面，只用于独立封面图。

### 9.5 人物一致性

1. 默认优先使用 2 人，只有内容确实需要时才使用 3 人。
2. 输出人物清单后，脚本、分镜图提示词、视频提示词、发布正文和真人实拍建议必须复用同一清单。
3. 人物数量、身份、性别、年龄感、位置、动作和是否说话必须一致。
4. 标题、脚本、分镜图提示词和视频提示词涉及的老人性别必须一致。
5. 所有说话人必须真实出现在画面内，不使用画外音。
6. 不新增、减少、合并或模糊人物。
7. 结尾购买引导角色必须来自人物清单，不能新增主播、销售或路人。

### 9.6 15 秒脚本

全片只有一个固定镜头、一个场景和一个产品角度。时间段只是同一镜头中的节奏划分，不代表切镜。

| 时间段 | 内容 |
|---|---|
| 0-4 秒 | 生活场景开场和一个购买前疑问 |
| 4-11 秒 | 围绕唯一卖点回答，并表现使用后的具体改善 |
| 11-15 秒 | 落到生活改善结果，并由已有角色自然完成购买引导 |

脚本以“时间段 / 画面内容 / 人物动作 / 对话口播 / 拍摄注意”表格输出。每个时间段必须明确所有人物是否在画面中以及分别在做什么。

口播自动统计字数并估算正常语速。超过 15 秒容量时自动压缩，不能通过加速到不自然语速解决。

### 9.7 结尾对话

结尾必须在一句自然对话中完成：

```text
买了 / 用了 / 换了爱优护电动轮椅后
+ 当前唯一卖点带来的实际改善或益处
+ 柔和引导有同类需求的人了解或购买
```

要求：

- 由人物清单中的已有角色说出；
- 只围绕当前核心痛点和唯一卖点；
- 不能提价格、优惠、活动、赠品、库存或限时信息；
- 不使用“赶紧下单、闭眼入、必买”等强促销表达；
- 其他人物在结尾继续自然同框；
- 若总口播过长，优先压缩前半段，不能删除改善益处和柔和购买引导。

### 9.8 单镜头和画面规则

- 视频时长约 15 秒，竖屏 9:16。
- 真实手机实拍感、自然光、生活化、干净明亮。
- 风格是买家体验、问大家答疑、邻居聊天或老人现身说法，不是详情页硬广。
- 全片只生成 1 个分镜，不切换镜头、场景、产品角度或产品款式。
- 产品优先保持正侧 45 度或轻微侧面角度。
- 镜头只允许轻微手持、轻微直线跟拍或轻微推近。
- 不出现多个轮椅、不同款轮椅或无关产品。
- 不在画面中设计字幕、标题、标签、箭头、价格或促销文字。
- 不编造用户未提供的重量、续航、价格、材质、专利、认证等参数。

### 9.9 电动轮椅品类专属动作规范

以下规范只对电动轮椅品类自动启用，不影响其他产品。

#### 直线运动

- 轮椅只能直线缓慢行驶、直线停下或静止交流。
- 禁止拐弯、转向、掉头、S 形路线、弧线、绕行、原地转圈、侧移和倒车转向。
- 老人坐在轮椅上时保持固定正侧 45 度角。
- 镜头只可沿直线路径轻微跟拍，禁止环绕。
- 轮椅始终保持同一方向、角度、结构和比例。
- 禁止转弯进电梯、拐弯进门、绕障碍物、路口转向，以及从正面转到侧面或背面。

#### 折叠、轻便、收纳和搬运

- 禁止展示正在折叠、展开或任何车架结构变化过程。
- 禁止复杂折叠操作、多角度展示和连续操作扶手、靠背、脚踏。
- 只能表现已经折叠好的状态静置、固定角度直线提起或直线放下。
- 可在后备箱旁、玄关等场景通过对话表达收纳方便，但不展示塞入后备箱的复杂动作。
- 提起过程中禁止旋转、改变朝向、斜向拖拽或改变产品角度。

如果某个卖点无法在这些稳定动作中表达，改用固定画面和自然对话，不强行设计复杂动作。

### 9.10 节点 2 自动检查

至少检查：

- 人物数量、身份和性别在全部模块中一致；
- 只有一个痛点、一个卖点、一个分镜和一个场景；
- 发布标题和封面标题符合长度及必含词规则；
- 无画面字幕和促销文字设计；
- 无未提供参数；
- 无转弯、绕行或动态折叠；
- 结尾包含改善益处和柔和购买引导；
- 口播能以正常语速在 15 秒内完成；
- 不触犯已确认经验规则。

检查失败自动重写，最多 3 次；仍失败只暂停该视频项目。

## 10. 节点 3：分镜图和封面图

### 10.1 生图模型选择

默认自动生图：

1. 当前环境有 Codex 原生生图能力时优先使用 Codex。
2. 没有 Codex 或原生能力不可用时，使用启动确认单中的生图 API。
3. 两者都不可用时在启动前拦截，不运行到节点 3 才询问。

### 10.2 产品参考图选择

- 自动分析产品文件夹第一层全部图片。
- 每条视频自动选择最适合场景和角度的参考图。
- 使用 1 张主参考图，必要时最多增加 2 张辅助图。
- 不同时传入角度差异过大的参考图，避免结构混乱。
- 记录实际使用的参考图、模型、提示词和生成时间。

### 10.3 分镜图生成

- 每条视频最终只保留 1 张分镜图。
- 比例固定为 9:16，使用模型支持的最高合理质量和清晰度。
- 产品外形目标与参考图达到用户定义的 90% 以上相似。
- 不允许车架、轮胎、扶手、脚踏、靠背、控制器等大面积变形。
- 产品颜色、比例和主要结构保持一致。
- Logo 图案、形状和内容不能改变；Logo 错误直接判定不合格。
- 人物数量、身份、性别、位置和场景必须与节点 2 一致。
- 画面不能出现字幕、标签、价格或异常文字。

每张最多自动尝试 3 次。失败版本保存在 `失败版本/`，不覆盖。三次仍不合格时只暂停该项目，其他项目继续，批次结束后统一汇报。

### 10.4 封面图参考库

技能包根目录固定创建：

```text
封面图参考/
```

- 所有产品共用。
- 只读取第一层图片。
- 用户可随时添加或删除参考图。
- 每条视频自动选择一张最合适的参考风格，不混合多种风格。
- 学习模式允许审核所选风格，自动模式按已验证经验自主选择。
- 只学习版式、标题层级、字体粗细、描边、配色、留白和构图关系。
- 不复制参考图中的产品、人物、品牌、Logo 或标题内容。

### 10.5 封面图生成

- 使用已验收通过的分镜图作为封面底图，不重新生成产品和人物。
- 通过程序准确排版节点 2 生成的约 5 字封面标题，避免 AI 生字错误。
- 不改变底图中的产品、人物和 Logo。
- 输出 9:16 高清封面图。
- 记录使用的风格参考图。

## 11. 节点 4：发布正文

本节正文品牌称呼和固定话题属于 `爱优护电动轮椅_淘宝天猫光合` 内容配置，其他产品不得复用。

输入：节点 2 最终脚本、发布标题、封面标题、人物清单、唯一痛点与卖点，以及节点 3 验收通过的分镜图。

每条视频输出一个 `发布正文.md`：

- 正文主体为 80 至 150 个汉字，标签不计入字数。
- 保持真实买家、老人或家属的生活化分享语气。
- 只围绕当前唯一痛点和卖点。
- 明确表达购买或使用爱优护电动轮椅后的改善和益处。
- 结尾加入柔和了解或购买引导。
- 不编造参数，不添加其他卖点。
- 人物数量、身份、性别、场景和产品状态与脚本及分镜图一致。

正文末尾固定追加，顺序不变：

```text
#爱优护电动轮椅 #ainsnbot高端智能电动轮椅 #电动轮椅 #老人专用电动轮椅
```

自动检查字数、固定标签、唯一卖点、人物一致性、改善益处、购买引导、编造信息和违规促销表达。

## 12. 节点 5：MiniMax-H3 参数与预算

### 12.1 固定模型

```text
平台：AutoDL.Art
模型：MiniMax-H3
接口：https://www.autodl.art/api/v1/minimax/v2/video_generation
时长：15 秒
比例：9:16
默认分辨率：768P
可选分辨率：2K
AIGC 画面水印：关闭
```

每次启动时提醒是否升级 2K。只有用户明确选择 2K 才使用 2K，否则使用 768P。

### 12.2 视频输入

- 节点 3 已验收的分镜图作为 `first_frame`。
- 节点 2 最终视频提示词作为文本输入。
- 提示词包含完整人物清单、声音特征、动作、对话内容和说话时间。
- 不单独调用 TTS。MiniMax-H3 原生生成画面、人物对白、嘴型、动作和场景环境音。

声音要求：

- 根据人物清单在提示词中自动匹配性别、年龄感和身份相符的声音；
- 不同人物声音应可区分；
- 未说话人物不抢话、不错误对口型；
- 只保留人物自然对白和轻微生活环境音；
- 不生成背景音乐；
- 不使用主播腔或广告腔。

### 12.3 费用参考

按用户 2026-08-26 提供的 AutoDL.Art 页面截图：

| 分辨率 | 会员价 | 15 秒会员价 | 原价 | 15 秒原价 |
|---|---:|---:|---:|---:|
| 768P | ¥0.45/秒 | ¥6.75 | ¥0.50/秒 | ¥7.50 |
| 2K | ¥0.72/秒 | ¥10.80 | ¥0.80/秒 | ¥12.00 |

- 输入音频免费。
- 5 张以内输入图片免费，超出部分按实时页面计费。
- 本流程每条使用 1 张首帧图，因此不产生输入图片费用。
- 价格可能变化，启动确认单必须使用当前平台价格重新计算，不能永久写死历史价格。

启动时同时显示基础预算和“初次生成 + 每条最多一次重跑”的最高预算。预计费用超过最高预算时不提交超额任务。

## 13. 节点 6：提交任务

### 13.1 触发方式

- 学习确认模式：节点 2 内容和节点 3 图片通过人工审核后自动提交，不逐条询问。
- 自动生产模式：全部规则检查通过后直接提交。
- 预算不足、API 失效等系统性问题才停止批次。
- 单条项目检查失败只暂停该项目。

### 13.2 提交前检查

检查项目文件完整性、人物一致性、唯一卖点、单镜头、动作限制、产品和 Logo 验收、口播时长、无字幕、无编造参数、API 配置、余额和预算。

检查不通过时自动修正并重新检查，最多 3 次。仍不通过只暂停该视频项目。

### 13.3 请求数据

核心请求结构：

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "节点2最终视频生成提示词"
    },
    {
      "type": "image_url",
      "role": "first_frame",
      "image_url": {
        "url": "节点3最终分镜图"
      }
    }
  ],
  "resolution": "768P",
  "duration": 15,
  "ratio": "9:16",
  "aigc_watermark": false
}
```

实际分辨率按启动确认单填写。

### 13.4 并发和防重复

- 默认同时运行 3 条任务，启动时可修改。
- 接口限流时自动降低并发，恢复后继续。
- 每条任务生成本地项目编号、请求哈希、提交状态和预算占用记录。
- 已有 `task_id` 的项目不重复提交。
- 同一请求哈希不能在同一批次提交两次。
- 提交前预留预计费用，完成后用真实用量更新。
- 请求超时且无法确认是否已被平台接收时，标记“提交状态待确认”，不盲目重提。

## 14. 节点 7：保存 task_id

AutoDL.Art 返回任务后立即保存：

- 本地视频项目编号；
- AutoDL `task_id`；
- 平台 `request_id`；
- 提交状态和时间；
- 模型、分辨率、时长和预计费用。

保存到：

```text
单条视频项目/任务信息.json
批次目录/批次任务表.json
```

必须先成功落盘 `task_id` 才进入轮询。批量提交结束后统一向用户汇报，不逐条发送消息。

## 15. 节点 8：轮询状态

- 默认每 20 秒查询一次，启动时可修改。
- 批量任务错峰查询，避免请求集中。
- 识别 `queued`、`running`、`succeeded`、`failed`、`cancelled`。
- 网络错误采用递增间隔重试，最多 5 次。
- 遇到限流时遵循平台返回的等待时间。
- 单条连续等待最长 60 分钟。
- 超过 60 分钟不判失败、不重新提交，只标记“查询超时，等待继续轮询”。
- 保留原 `task_id`，下次继续查询。
- 每次状态变化立即写入任务信息。

## 16. 节点 9：下载和技术校验

- 某条任务成功后立即下载，不等待整个批次。
- 先保存为 `视频.mp4.part`，校验通过后原子改名为 `视频.mp4`。
- 检查 MP4 容器、可解码性、文件大小、约 15 秒时长、9:16 画幅、预期分辨率、有效音轨和非全程静音。
- 自动提取开头、中间和结尾画面用于验收。
- 校验通过后计算文件哈希并写入任务记录。
- 下载或文件损坏最多重试 4 次。
- 仍失败只暂停该任务，其他任务继续。

## 17. 节点 10：批量人工验收

每个批次只生成一份交互式：

```text
批次验收报告.html
```

报告中每条视频是一张独立卡片，包含：

- 视频编号和视频播放；
- 封面图；
- 视频发布标题和封面标题；
- 对应卖点；
- 自动验收摘要；
- AutoDL `task_id`；
- 预计及实际费用；
- “通过 / 不通过”选择；
- 不通过原因；
- 修改或重跑建议。

只有所有视频都已选择通过或不通过，且不通过项填写原因后，“完成验收”按钮才可提交。

本地 Python 服务接收提交并生成：

```text
批次验收结果.json
批次验收结果.md
```

同时把每条结果写入对应项目的 `人工验收结果.md`。没有浏览器环境时回退为 Markdown 验收表。

自动验收材料包括：

```text
视频.mp4
验收预览图.jpg
自动验收报告.md
语音转写.txt
```

自动报告检查产品和 Logo、人物、单镜头、动作限制、字幕、对白、说话人、嘴型、改善益处、购买引导、背景音乐和历史错误规则。无论自动结果如何，最终视频仍由用户人工验收。

## 18. 节点 11：复盘与一次重跑

用户提交批量验收结果后，每条不通过视频执行：

```text
读取失败原因
→ 对照脚本、分镜、提示词和成片
→ 判断错误节点
→ 形成候选经验
→ 修改对应内容
→ 重新检查
→ 计算重跑费用
→ 重跑一次
→ 再次进入人工验收
```

问题分流：

- 脚本或人物逻辑错误：返回节点 2。
- 分镜图或产品外观错误：返回节点 3。
- 发布正文错误：只返回节点 4。
- 视频提示词、动作、对白或嘴型错误：修改视频提示词后重新提交。
- API 或下载故障：不修改创作内容，只做技术重试。
- 模型能力不足：改用稳定表达，并记录 MiniMax-H3 能力边界。

每条只允许初次生成和一次重跑：

```text
视频版本/
├─ V01_初次生成/
└─ V02_唯一一次重跑/
```

第二版仍不合格时停止该项目并标记“需要人工专项处理”，不继续产生费用。最终通过版本复制为项目根目录的 `视频.mp4`。

## 19. 经验学习系统

### 19.1 经验范围

复盘不限于当前已想到的问题，采用开放标签，可自动创建新分类。至少覆盖：

- 产品素材与参考图选择；
- 卖点准确性、策划、脚本、标题和正文；
- 人设、人物数量、性别、关系和场景；
- 分镜连续性、图片提示词和视频提示词；
- 产品结构、Logo、人物畸变和动作可实现性；
- 镜头、方向、折叠和机械结构变化；
- 模型和工作流适配；
- 分辨率、时长、画幅、成本和耗时；
- API、轮询、下载和文件故障；
- 平台发布、合规和人工验收反馈；
- 后续发现的未知问题类型。

### 19.2 经验层级

```text
全局经验
品类专属经验
产品专属经验
模型 / 工作流专属经验
```

MiniMax-H3 做不好的效果只记录为该模型或工作流的能力边界，不永久认定为所有 AI 都无法完成。

### 19.3 生命周期

```text
新发现
→ 候选经验
→ 修改并验证
→ 正式规则
```

- 用户反馈和首次失败只形成候选经验。
- 重跑通过，说明规避方法有效，可升级为正式规则。
- 重跑仍失败，记录为能力边界，不把失败方案升级为规则。
- 学习确认模式下，即使重跑通过，也要把候选经验放入批次复盘报告，由用户确认后才激活为正式规则。
- 自动生产模式只能自动应用已经正式确认的规则；新发现仍先进入候选经验，不能因一次自动判断直接污染正式规则库。
- 规则可以修订、降级和废弃。
- 正式规则参与后续生成前检查。

## 22. 错误处理

### 22.1 启动前拦截

- 产品路径不存在或没有图片；
- 文本、生图或 AutoDL API 配置缺失；
- API 鉴权失败或余额不足；
- 预计费用超过预算；
- 模型不支持所选参数；
- 封面参考库没有可用图片。

### 22.2 单条隔离

内容、分镜图、提交、轮询、下载、视频验收等单条失败均不阻塞其他项目。批次结束后统一报告所有失败和待人工确认项目。

### 22.3 系统性暂停

只有 API 整体失效、余额不足、预算超限或必要配置失效才暂停整个批次。

## 23. 测试策略

### 23.1 单元测试

覆盖数量分配、路径和产品名、标题规则、正文长度与标签、人物一致性、动作限制、口播时长、预算、状态机、防重复和重跑次数。

### 23.2 模拟 API 测试

模拟文本、生图和 AutoDL API 的成功、失败、超时、限流、任务状态、下载链接和损坏文件，不产生费用。

### 23.3 文件与恢复测试

验证中文路径、独立目录、中断恢复、防重复扣费、版本保留、验收写回和经验分类。

### 23.4 验收页面测试

使用模拟视频测试播放、选择、原因必填、完成提交、JSON/Markdown 输出、复盘和重跑队列。

### 23.5 真实付费冒烟测试

实现完成后，使用“1 个产品 + 1 个卖点 + 1 条 15 秒 768P 视频”验证完整链路。按当前参考价格，视频费用约 ¥6.75。必须在测试前由用户明确确认实时费用和预算，不能默认发起付费任务。

## 24. 完成标准

满足以下条件才视为第一版完成：

1. Codex、WorkBuddy、Hermes 和通用 Agent 至少都具备明确启动入口。
2. 启动确认单能一次性收集所有运行参数。
3. 任意产品文件夹能被扫描并创建独立输出批次。
4. 卖点能正确平均分配，且一条视频只使用一个卖点。
5. 节点 2 输出全部规定内容并通过规则检查。
6. 节点 3 能生成、验收和版本化保存分镜图及封面图。
7. 节点 4 正文长度、固定标签和人物一致性正确。
8. AutoDL.Art MiniMax-H3 能提交、保存 `task_id`、轮询、下载并恢复。
9. 预算、并发、防重复和失败隔离有效。
10. 批量验收页面能收集通过、不通过和原因。
11. 不合格视频最多自动重跑一次，版本不覆盖。
12. 候选经验只有在验证有效后才能升级为正式规则。
13. 所有凭据不会泄漏到代码、日志或输出文件。
14. 自动化测试通过，并在用户批准预算后完成一次真实付费冒烟测试。
