# 内容生成契约

文本模型输出结构化 JSON，每条只表达一个卖点。内容 JSON 只给出场景、人物、动作、对话和构图意图；外部提交前由提示词合同补齐不可变块。

## 必填字段

`video_id`、`selling_point`、`publish_title`、`cover_title`、`people`、`storyboard_people`、`script_segments`、`storyboard_prompt`、`last_frame_prompt`、`video_prompt`、`publish_body`、`hashtags` 必须齐全。`people` 恰好为老人和一名陪护者/家属两个不同 ID，二人全程在画面内；`script_segments` 按时间递增覆盖 0–15 秒。

```json
{
  "video_id": "V001",
  "people": [{"id": "P1", "identity": "老人"}, {"id": "P2", "identity": "陪护者或家属"}],
  "storyboard_people": ["P1", "P2"],
  "script_segments": [
    {"start": 0, "end": 4, "speaker_id": "P2", "dialogue": "一个购买前问题"},
    {"start": 4, "end": 11, "speaker_id": "P1", "dialogue": "围绕唯一卖点的回答"},
    {"start": 11, "end": 15, "speaker_id": "P1", "dialogue": "改善与下单类行动指令"}
  ],
  "storyboard_prompt": "渠道支持的原生分辨率 的固定中远景首帧",
  "last_frame_prompt": "渠道支持的原生分辨率 的连续合理尾帧",
  "video_prompt": "0–15 秒一个连续镜头的封闭双人对话"
}
```

## 四个生成提示词上下文

`storyboard_prompt`、`last_frame_prompt`、`cover_prompt` 和 `video_prompt` 都必须以产品参考图为输入，并在提交边界加入同一锁定语句：**产品参考图是唯一产品依据**。禁止用文字重新描述产品外观；禁止重新设计、补画、删减、替换或推测任何产品部件。内容字段不得出现外观、颜色、形状、材质或组件描述。视频提示词还必须原样包含运行时合同短语：`一镜到底`、`固定机位`、`完整双人对话口播`。

三张图片必须请求**渠道支持的原生分辨率**、9:16，**禁止本地放大**。产品、老人和陪护者完整位于安全区；固定中远景，不用局部特写。尾帧以分镜图为参考独立生成，只描述同一画面内已指定动作的结束状态，不复用首帧，也不另创背景或构图。

视频是分镜画面的局部动画，不是根据台词重新拍摄：分镜图是全程唯一画面基准。背景、构图、光线、人物身份与服装、产品外观和数量全程一致。只允许说话口型、自然微表情及分镜明确指定的产品运动；未指定运动时产品保持原位。禁止运镜、换景、插入空镜、特写或根据卖点联想无关画面。语义一致性不能仅凭技术解码通过来宣称；已有错误视频不得自动重新付费生成。

## 指令自洽与产品运动确认

必需短语齐全不代表内容自洽。编译及提交校验还会拒绝肯定式运镜、切换场景、插入空镜等冲突指令；禁止运镜等否定句不应误判。旧内容触发video.visual_conflict时报告冲突并修改未提交内容，不用新锁定块掩盖旧指令。该检查是保守的词法检查，不宣称覆盖任意自然语言或验证实际视频画面。

未确认的产品运动默认不允许。只有用户明确确认分镜动作后，宿主才可将原意逐句记录到该视频的_工作文件/生成过程/分镜动作确认.json：包含confirmed_by_user=true、当前已验收分镜图的storyboard_sha256，以及motion_clauses字符串数组。每条填写一个无逗号/句号分隔的完整动作子句；视频提示词必须原样匹配对应子句。不得让内容生成模型自行写确认记录，不得从video_prompt或“分镜已指定”字样反推用户确认。没有记录则产品保持原位；分镜哈希变化使旧记录失效。记录只确认动作，不构成付费重生成授权。

用户明确确认的示例记录：{"confirmed_by_user":true,"storyboard_sha256":"当前分镜图的实际SHA256","motion_clauses":["产品带人缓慢连续向前移动"]}。只有用户确实要求该动作才可使用，不把示例当默认值。

已有提交请求、已提交任务与费用记录保持不变。发现旧指令冲突时暂停该次新提交并报告；不要覆盖已绑定请求或自动启动V03。

## 封闭对话和声音

本地AutoDL客户端原样透传prompt，只映射图片字段；尚未核实服务端是否改写。新提交由编译器统一生成H3结构：首尾帧对齐说明、integrated_multimodal_description、overall_soundscape、non_diegetic_music。固定说话人映射为(S1)/(S2)，台词只在<d>[Chinese]实际台词</d>内出现一次。身份、动作、静默说明均放在标签外。video_prompt只提供未包装场景，不预写<d>标签或核心字段；编译器拒绝重复包装和台词标签注入。

script_segments的start/end是内容时段，不是整段必须发声。编译器在下一人开始前保留至少0.4秒无人声停顿，片尾也留0.4秒，已有更长停顿不缩短；停顿双方闭嘴、无气声/附和/伪语音。保留全部台词文字，不擅自改词；按可用发声时间每秒最多5个汉字做保守长度检查，过长则先精简未提交内容，不抢读或挤掉停顿。此为提示词时序约束，不保证模型生成的真实音频精确遵守。

格式参考：https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md 。只有原生口播方案，不使用独立配音或口型同步替换。

- 0–4 秒仅提问；4–11 秒仅回答唯一卖点；11–15 秒给出改善和明确下单类行动指令。
- 每句 `dialogue` 只出现一次，只由对应 `speaker_id` 发声；正确脚本文字也不允许重复、改词或增加说话者。
- **非当前说话者嘴巴闭合且完全不发声**；**清单之外零人声**，无画外音、无旁白、无群众说话、无 BGM。
- 视频为 0–15 秒一个连续镜头、固定中远景、固定机位；禁止切镜、跳切、转场、景别突变、加速抢读、漏词和截断尾句。

全部口播最多49个汉字；按自然语速完整说完并留出停顿，必要时自动精简。校验失败时修改 JSON 再运行 `workflow_cli.py validate-content`；不得绕过校验直接提交。

## 人工反馈定位知识（不得注入生成提示词）

人工反馈可记录“部件错位、外观变形、产品被替换”等诊断现象，并据此回看产品参考图、候选 SHA-256 和时间点。此节只用于问题定位，任何产品组件、颜色、形状或结构事实都不得写入四个生成提示词或模型内容字段。
