# 产品视频低成本自动化改造设计

## 目标

把 `product-video-pipeline` 从“Hermes/DeepSeek 每一步重新判断并调用工具”的 Agent 驱动流程，改造成“模型负责创意、脚本负责执行、用户只处理必要授权”的状态机流程。

改造后的技能用于自动批量生产产品视频，并满足以下目标：

- 显著减少 DeepSeek API 调用次数、重复上下文和推理 token；
- 图片固定通过 GPT 网页端生成；
- 图片不经过人工审核或模型二次视觉审核；
- 机械操作、技术校验、轮询、下载、归档和恢复均由本地脚本执行；
- 保留预算、重复扣费和失败重跑保护；
- 最终视频仍由用户人工验收。

## 当前问题

当前技能包包含约 4 万字符的规则与配置。相同规则分散并重复出现在 `SKILL.md`、11 节点流程、生图路由、AutoDL、验收、学习和交付契约中。

执行过程中又要求 Agent 在初始化、进入节点、生成图片、提交视频和验收时反复读取规则。Hermes 会在工具调用之间重新请求 DeepSeek，并携带此前的对话、规则全文和工具结果，导致输入上下文不断增长。

底层 `workflow_cli.py` 和 `autodl_h3.py` 已经具备大量确定性功能，但目前主要由 Agent 逐步编排，因此这些无需模型判断的动作仍产生了模型回合。

## 采用方案

采用“脚本状态机 + 少量模型节点”方案。保留并复用现有脚本，在其上增加统一批次调度器；不重写为长期运行的独立服务。

没有采用仅修改提示词的方案，因为它无法保证 Hermes 不拆分工具回合。没有采用完整服务化重写，因为当前批量规模不需要额外的服务部署、数据库和运维成本。

## 总体架构

系统分为三层：

1. 创意层：DeepSeek 只生成结构化内容、台词和图片/视频提示词，并在确定性脚本无法处理的异常发生时提供一次诊断。
2. 执行层：Python 状态机负责目录、规则、网页生图任务编排、文件处理、技术校验、AutoDL 提交、轮询、下载、验收材料和恢复。
3. 授权层：用户只处理首次配置与预算确认、V02 付费重跑授权和最终视频人工验收。

正常数据流：

```text
启动清单与预算确认
→ 一次生成整批结构化内容和提示词
→ GPT 网页端生成分镜、尾帧、封面
→ 本地技术检查与自动晋升
→ AutoDL dry-run
→ 授权预算内自动提交 V01
→ 独立轮询与下载
→ 本地媒体技术检查
→ 生成批量验收报告
→ 用户最终验收
```

## 状态机

新增统一调度器 `scripts/pipeline_runner.py`，以批次和单条任务状态文件为事实来源。核心状态为：

- `WAITING_START_APPROVAL`：等待启动配置、数量和预算确认；
- `RUNNING_AUTOMATICALLY`：执行内容、图片、提交前检查等自动节点；
- `WAITING_PAID_APPROVAL`：尚未取得 V01 总预算授权；
- `GENERATING`：任务已提交并由脚本轮询；
- `WAITING_FINAL_REVIEW`：视频候选已下载并等待用户验收；
- `WAITING_RERUN_APPROVAL`：V01 不通过，等待用户授权 V02；
- `COMPLETED`：最终视频通过且七项产出审计成功；
- `BLOCKED`：发生无法自动恢复的技术错误、配置错误或预算错误。

调度器一次运行到下一个真正需要用户决定的状态。节点成功后直接继续，不返回 Hermes 让模型决定下一步。

状态写入采用原子更新。每个付费提交保存请求哈希和服务端任务 ID；未知提交状态进入 `BLOCKED`，不得盲目重复提交。

## 图片生成规则

分镜图、尾帧图和封面图固定使用 GPT 网页端，不再按 Codex、ChatGPT 网页端、第三方 API 的顺序回退。

每次网页生成尽可能在一个浏览器自动化动作内完成提示词提交、等待结果、定位生成图和下载，避免把点击、等待和检查拆成多个 DeepSeek 回合。

图片不进行以下审核：

- 不等待用户人工通过；
- 不调用 DeepSeek、GPT 或其他视觉模型做二次视觉审核；
- 不检查产品相似度、结构变形、人物身份、构图质量和封面文字准确性。

图片仍执行不产生模型费用的本地技术检查：

- 文件存在且大小非零；
- 文件能够解码且为允许的图片格式；
- 画幅为 9:16；
- 最终尺寸为 `2160×3840`；
- 计算并记录 SHA-256；
- 分镜和尾帧的 SHA-256 不同；
- 文件位于当前任务 `_工作文件/生成过程`。

GPT 网页端生成 `1152×2048` 等同 9:16 图片时，允许确定性等比放大到 `2160×3840`。不得拉伸非 9:16 图片，也不得通过裁切、补画、代码叠字或程序修字改变内容。

下载失败、空文件或无法解码时自动重新下载一次。第二次仍失败则进入 `BLOCKED`。视觉质量问题不阻断流程，其风险由最终视频验收承担。

技术检查通过后，脚本使用本批次自动执行授权记录 `passed` 事件并自动晋升，无需 Agent 再次解释或确认。

## DeepSeek 调用边界

正常情况下，DeepSeek 只用于：

- 为整批任务一次性生成结构化内容、台词、发布文本及图片和视频提示词；
- 结构化生成无法通过本地内容契约时，进行一次定向修正；
- 确定性脚本无法分类的异常，进行一次诊断；
- 向用户生成必要的简短状态或最终汇报。

DeepSeek 不用于：

- 扫描文件、创建目录或分配卖点；
- 读取并转述规则；
- 浏览器附件数量检查；
- 图片下载、尺寸转换、解码和哈希计算；
- dry-run、请求哈希、任务记录；
- 每 20 秒轮询；
- 视频下载、ffprobe 和解码检查；
- 文件归档、产出晋升、审计和状态更新。

调度器维护每批次和每条视频的模型调用计数。达到配置上限时，不再自动请求 DeepSeek；确定性节点继续运行，需要模型判断的节点进入 `BLOCKED` 并返回简短原因。

工具和脚本输出使用紧凑 JSON，只返回状态、节点、路径、尺寸、哈希、任务 ID、错误代码和下一个闸门。完整日志保存在任务目录，不写回对话上下文。

## 规则压缩

`SKILL.md` 只保留：

- 精确触发条件；
- 三个用户授权闸门；
- 图片免审风险声明；
- 调度器唯一入口；
- 发生 `BLOCKED` 时的处理方法。

重复的机器规则合并到一个紧凑、带版本号的规则清单。调度器初始化时加载一次并把规则版本和摘要写入批次状态。规则未变化时，节点不得重复向模型加载全文。

现有详细 Markdown 文档可以保留为开发和审计资料，但正常执行路径不再要求 Hermes 反复读取。

学习规则只在用户对当前候选提出明确纠正或不通过原因时触发。记录、验证和升级由脚本完成，不因普通状态消息重新加载完整学习文档。

## 授权和费用边界

保留以下人工闸门：

1. 启动阶段确认产品、数量、分辨率、实时单价和总预算；
2. V01 失败后单独确认是否付费生成 V02；
3. 最终视频人工验收。

首次总预算确认后，预算范围内的全部 V01 可以自动提交。启动授权不包含 V02。V02 不通过后停止，不生成 V03。

图片网页生成不增加人工审批。图片视觉错误、人物错误、产品结构错误或封面错字不会阻止 V01 提交；用户已接受这些风险由最终视频验收发现。

## 错误处理与恢复

- 单条任务失败不阻塞批次内其他任务；
- API 余额不足、总预算超限、鉴权失效或整体服务不可用时暂停整个批次；
- 图片下载技术失败自动重试一次；
- AutoDL 查询网络错误沿用有界重试，轮询由脚本内部完成，不产生模型回合；
- 提交超时且远端状态未知时禁止自动重提；
- 视频下载继续使用 `.part`、原子改名和有界重试；
- 重启后从持久化状态和任务 ID 恢复，不重新执行已完成节点；
- 所有错误仅把摘要返回 Hermes，完整证据落盘。

## 兼容与迁移

保留现有批次目录、七项最终产出、`_工作文件`、验收事件、SHA-256、任务 ID 和 AutoDL 请求记录格式，避免破坏已有批次。

现有 `workflow_cli.py` 和 `autodl_h3.py` 继续作为底层命令模块。新增调度器优先调用可复用函数；必要时增加新的聚合子命令，但不删除已有命令。

当前工作区已有与技能包相关的未提交修改。实施时必须先逐文件检查差异，只在现有内容上增量修改，不覆盖或撤销用户已有改动。

## 测试与验收标准

至少覆盖以下自动化测试：

- 状态机正常从启动授权运行到最终验收闸门；
- 同一节点不会因恢复执行两次；
- 同一请求哈希不会重复付费提交；
- 未确认 V01 预算时无法付费提交；
- V01 失败后没有 V02 授权时无法重跑；
- V02 后无法创建 V03；
- GPT 网页下载图片通过本地技术检查后自动晋升；
- 图片视觉内容不会触发审核调用；
- 图片解码失败只重试一次并进入 `BLOCKED`；
- 分镜与尾帧哈希相同会被拒绝；
- 轮询和下载期间模型调用计数不增加；
- 中断恢复不重复生成图片或视频；
- 七项产出审计规则继续有效；
- 旧批次仍可由现有命令读取和整理。

完成验收指标：

- 正常批次的机械节点不产生 DeepSeek 调用；
- 正常任务能够一次运行到下一个人工闸门；
- DeepSeek 调用次数能够在状态文件中审计；
- 完整日志不进入模型上下文；
- 所有现有测试和新增测试通过；
- 通过一次不提交付费任务的端到端 dry-run 验证恢复、图片技术检查和最终闸门。

## 明确不在本次范围内

- 不开发常驻 Web 服务、数据库或新的管理后台；
- 不取消最终视频人工验收；
- 不自动授权 V02；
- 不增加 V03；
- 不保证 GPT 网页生成图片的视觉质量或封面文字准确率；
- 不改变 AutoDL 的模型、15 秒时长和首尾帧基本工作流。
