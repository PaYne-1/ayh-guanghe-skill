# 全局产品视频任务窗口路由设计

## 目标

确保每个新的 Codex 任务窗口，无论用户第一条消息是什么，都自动进入 `product-video-pipeline` 的启动沟通流程；已有任务窗口则不会因为普通内容被强制重置。

## 路由定义

### 新任务窗口

新任务窗口是没有既有用户任务上下文的窗口。该窗口的第一条用户消息无条件触发 `product-video-pipeline`，不要求出现“视频、产品、开始新任务”等关键词。

触发后必须发送完整三段式启动清单：

1. 你需要提供的内容；
2. 本次配置明细；
3. 请你回复。

第一条消息中已经提供的路径、产品、卖点、数量或配置自动带入清单并标记为“已提供”。用户回复清单前，不执行原始请求中的扫描、创建、查询、生图、dry-run 或付费动作。

### 已有任务窗口

已有任务窗口是已经存在用户任务上下文的窗口。普通消息继续当前任务，不重新发送启动清单。

当用户表达“开始新任务、开始新项目、换个产品、再开一批”或同义的新任务意图时，只询问一次：

> 是否开始全新的产品视频任务？

- 用户确认“是”：清除当前任务的临时启动上下文，发送完整三段式启动清单。
- 用户确认“否”：保持当前任务，不触发产品视频新任务清单。
- 用户尚未回答：不扫描、不创建批次、不查询价格、不生成媒体、不 dry-run、不调用付费接口。

## 授权边界

- 上一个任务的“本次直接执行”、付费授权、预算确认和临时配置不得带入新任务。
- 历史安全环境变量可以作为“已接入”状态展示，但仍需在新任务清单中确认是否继续使用。
- 新窗口无条件触发仅表示进入启动沟通，不表示授权执行用户原始请求。

## 验收场景

| 场景 | 预期行为 |
|---|---|
| 新窗口第一条消息为“你好” | 直接发送三段式产品视频启动清单 |
| 新窗口第一条消息为一段代码问题 | 仍先发送三段式产品视频启动清单，不执行代码请求 |
| 新窗口第一条消息已包含产品目录和卖点 | 发送清单，并将相关字段标记为已提供 |
| 旧窗口说“开始新任务” | 只询问是否开始全新的产品视频任务 |
| 旧窗口回答“是” | 发送三段式启动清单 |
| 旧窗口回答“否” | 继续当前任务，不发送清单 |
| 旧窗口普通追问 | 继续当前任务，不触发新任务流程 |

## 测试策略

- RED：先让离线自检断言全局 `AGENTS.md` 和技能文档必须包含新窗口无条件触发、旧窗口确认触发等契约，确认当前版本失败。
- GREEN：最小修改三份规则文件，使离线自检通过。
- 新窗口人工验证：新建任务窗口，只发送任意内容，确认直接出现三段式清单。
- 旧窗口人工验证：在已有窗口说“开始新任务”，确认只出现一次切换确认问题。

## 非目标

- 不修改三段式清单的字段。
- 不改变产品视频的11节点流程、预算规则或付费授权要求。
- 不自动执行新窗口第一条消息中的其他任务。
- 不把旧任务的临时授权继承到新任务。
