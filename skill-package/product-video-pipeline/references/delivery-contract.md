# 交互与最终交付契约

## 用户明确偏好

- 启动时必须选择 `GPT 网页端` 或 `第三方 API` 生成分镜、尾帧和封面。批准后的已锁定生图渠道在批次内禁止自动切换；`gpt_web` 使用当前已登录浏览器会话且禁止服务器端 OpenAI API，`third_party_api` 仅使用已封存的非密钥配置。
- 用户要求提示词或候选在当前对话确认时，直接在当前对话展示；图片和视频使用可渲染的绝对路径，Windows 路径统一使用正斜杠并用尖括号包裹含空格的目标。
- 启动和 V01 总预算批准后连续执行，直到 V02 单视频费用授权、最终视频验收或硬阻断；图片不设置人工审核节点，也不得要求用户重复回复“继续”。
- 所有封面都把已确认的封面文字写入已锁定生图渠道的生图提示词，一次生成完整封面；不得先生成底图再调用代码、脚本或画布叠字。生成结果不进行人工图片审核，也不进行模型视觉审核，通过免费技术检查后直接进入下一步。
- 已锁定生图渠道的原图为 `1152×2048` 时可等比归一化为 `2160×3840`，并记录原图尺寸、原图哈希、处理参数和结果哈希，不增加确认节点。不得拉伸、裁切、补画或在尺寸处理中新增、替换、重绘文字。
- 若原图不是 9:16、无法解码或不能等比归一化，则按技术重试处理；不做清晰度或美观度视觉评分，也不得用程序修字。

## AutoDL 恢复规则

- 提交前以 AutoDL 当前工作流页面或同工作流最近成功调用参数为准。`minimax_h3_lightx2v_v5_15s` 当前 API 使用 `ref_image_0`、`ref_image_1`；本地仍把两张素材语义记录为 `first_frame`、`last_frame`，提交脚本负责映射。
- 响应没有 `task_id` 时保存并报告 `code`、`msg`、`request_id`。先检查调用日志是否出现新任务或新消费；存在则恢复其任务 ID，不存在才可在原付费授权范围内修正参数并重试。
- 未核实远端状态时不得盲目重提，防止重复扣费。

## 最终交付格式

1. 从 `标题.txt` 只读取以 `发布标题：` 开头的行，删除字段前缀和首尾空白；不得把同一文件中的“封面标题”拼进视频文件名。
2. 文件名中的中文、英文特殊标点替换为单个空格，连续空格折叠；保留汉字、字母、数字，扩展名为 `.mp4`。
3. 示例：`发布标题：路面湿滑也不慌，这款电动轮椅走得稳` → `路面湿滑也不慌 这款电动轮椅走得稳.mp4`。
4. 在当前对话直接展示可播放视频。
5. 最终回复最后一项必须写出完整的最终文件夹路径；同时写出完整视频文件路径。
6. 最终批次报告必须写明已锁定的生图渠道；若选择 `第三方 API`，还必须汇总独立图片 API 成本账本（单张价格、图片 API 批次预算、已保留/已发生金额及余额），不得与文本或 AutoDL 视频费用混合，也不得输出密钥值。

## 完成交付门槛

用户明确通过视频后，必须针对该候选追加 `passed` 验收事件并绑定不可变候选路径与 SHA-256；内部逻辑产物名仍为 `视频.mp4`，一级物理文件名必须是清洗后的发布标题。随后运行 `audit-outputs`，确认七项最终产出全部有效、`missing`/`demoted`/`errors` 均为空，并执行视频全片解码检查。只有这些条件成立且任务状态写为 `COMPLETED`，才可回复任务完成。

运行器在下载后通过 ffprobe 检查时长、尺寸和音轨，再用 ffmpeg 完整解码画面与音轨；保存 `_工作文件/验收记录/视频技术检查.json`。用户结果必须与此证据的候选路径、版本和 SHA-256 一致，才能晋升。候选字节发生变化必须重新检查，dry-run 不能提供此证据。最终状态同时写回 `流水线状态.json`、`任务信息.json` 和 `批次任务表.json`。
